## Текущее состояние

- Открытая DAW на Rust для Linux и Windows, пишется по методу чистой комнаты
  (только свои спецификации, без чужого кода).
- Спецификации 001–054 закрыты и влиты в `main` (SPEC-050 — PR #63,
  SPEC-051 — #66, SPEC-052 — #67, SPEC-053 — #68, SPEC-054 — #69).
- SPEC-050 закрыта, кроме §1: перетаскивание окна за полосу не работает (см.
  «Известные баги», п. 3) — отложено владельцем как некритичное.
- Объём: ~45 тыс. строк Rust в трёх крейтах; 57 файлов в `specs/`. У каждой
  закрытой спецификации есть тесты; гейт `fmt`/`clippy -D warnings`/`test`
  зелёный на `main`.
- Сборки: AppImage (Linux) и zip (Windows) в GitHub Releases, версия берётся из
  тега (в `Cargo.toml` остаётся `0.1.0`).

## Архитектура

Три крейта, строго по слоям (подробнее — `docs/ARCHITECTURE.md`):

```
crates/audio-core   движок, #![forbid(unsafe_code)], без платформенных API
crates/daw-app      оболочка: файлы, кэш, метры, бэкенды (CPAL за фичей realtime)
crates/daw-gui      окно на eframe/egui: таймлайн, микшер, инспектор
```

Правило реального времени: код в `Graph::process`, `Renderer::render` и
аудиоколбэке не аллоцирует, не блокирует и не делает I/O; обмен с UI — через
`rtrb`.

Вендорный winit: `vendor/winit` — это 0.30.13 плюс один патч (X11:
`XdndPosition` → `CursorMoved`), подключённый через `[patch.crates-io]`.
Описание и порядок обновления — `vendor/winit/SOUND_PRO_PATCH.md`: при переходе
eframe на новый winit копируем релиз из registry, переносим хунк (или убираем
вендор, если upstream сам шлёт `CursorMoved`), правим `[patch.crates-io]`,
делаем `cargo update -p winit` и прогоняем полный CI. Патч нельзя терять при
обновлении зависимостей.

## Что вошло в SPEC-051 — SPEC-054

**SPEC-051 (v0.1.29, PR #66) — маршрутизация шин.** Отправка с шины на шину,
solo/mute на шине, микшерный GUI. Топологическая сортировка порядка шин
считается в `Mixer::new` (вне аудио-пути); `process` без аллокаций —
предвыделенные буферы и фиксированный массив `[BusSend; MAX_BUSES]` на шину.
Solo/mute шины глушит только возврат в мастер: исходящие посылы шины
продолжают идти. Циклы отвергаются при валидации проекта (DFS).

**SPEC-052 (v0.1.30, PR #67) — экспорт микса.** Выбор битности (16/24 бит) и
частоты дискретизации, нормализация по пику к целевому dBFS, прогресс в фоне.
Идёт через существующий offline-render с мастер-цепочкой.
Код: `crates/audio-core/src/wav.rs` (энкодер), `crates/daw-app/src/lib.rs`,
тесты — `crates/daw-app/tests/export.rs`.

**SPEC-053 (v0.1.31, PR #68) — импорт FLAC и OGG Vorbis** рядом с WAV/MP3.
Чисто-Rust декодер (`symphonia`: flac + vorbis + ogg), пользователь ничего не
устанавливает. Стерео и моно, любая частота, FLAC 16/24 бит; `.flac`/`.ogg`/
`.oga` есть в диалогах и в drop-фильтре; битый файл даёт понятную ошибку в UI
без паники. Код: `crates/daw-app/src/audio_file.rs`, фикстуры
`crates/daw-app/tests/data/sine*.flac`, `sine.ogg`.

**SPEC-054 (v0.1.32, PR #69) — темпо-трек / темпо-карта.** Упорядоченные точки
(тик + BPM), первая всегда на тике 0; скалярный `tempo_bpm` стал первой точкой,
старые проекты открываются без изменений, карта сериализуется только при >1
точке. Единый путь конвертации тик↔сэмпл заменил скалярный BPM везде
(метроном, сетка/снап, линейка тактов, MIDI-секвенсор, экспорт). Изменение
темпа ступенчатое, без рамп. `MAX_TEMPO_POINTS = 256`, BPM 30–300.
Realtime: карты строятся вне аудио-пути и передаются через `rtrb`-кольцо, старые
карты возвращаются вторым кольцом и освобождаются на control-потоке; в
аудио-пути нет аллокаций и локов. Код: `crates/audio-core/src/transport.rs`,
`project.rs`, `session.rs`, `crates/daw-app/src/playback.rs`,
`crates/daw-gui/src/{main,lib,timeline,layout}.rs`.

## Известные баги

| # | Симптом | Причина / состояние |
|---|---|---|
| 1 | При перетаскивании файла регион встаёт не под курсором (зависит от размера экрана), а не туда, куда указывает мышь | **Исправлено (PR #63).** winit 0.30.13 на X11 не шлёт `CursorMoved` во время внешнего XDND-драга. В вендоренном winit (`vendor/winit`, 0.30.13 + патч) `XdndPosition` превращается в `CursorMoved`, поэтому egui-указатель живёт во время драга. Призрак и дроп используют **один** источник позиции (`egui`/XDND, фолбэк на `XQueryPointer`) и одну функцию пересчёта, так что регион ложится ровно туда, где был призрак. Проверено владельцем вживую. |
| 2 | Дроп на существующую дорожку с регионами всегда создаёт новую | **Исправлено (PR #63).** Следствие #1: без верной позиции hit-test дорожки промахивался. Чинится вместе с #1 (единый источник позиции); проверено владельцем вживую. |
| 3 | Перетаскивание окна за полосу (SPEC-050 §1) **не работает** | У окна нет панели, за которую его тянуть (`window_drag_commands` отвечает только на голую полосу панели управления). **Отложено владельцем как некритичное**; кнопки окна в фуллскрине при этом работают (v0.1.34) и опираются на локальный флаг `fullscreen`, а не на `ViewportInfo` (на XWayland он ненадёжен). |
| 4 | Приложение на Wayland идёт через XWayland | eframe включён без фичи `wayland`: winit 0.30.13 не умеет DnD на Wayland. Включать нельзя, пока не будет своя реализация. |
| 5 | AppImage на чужом дистрибутиве не открывал устройство вывода (Play не стартовал) | **Исправлено (v0.1.34, PR #71).** AppImage бандлил свой ALSA (Ubuntu 22.04) и форсировал `LD_LIBRARY_PATH`/`ALSA_PLUGIN_DIR`; на Fedora его PipeWire-плагин не находился. Теперь используется хостовый ALSA + PipeWire. Если устройство не открылось, транспорт идёт по тихим часам (`PlaybackEngine::advance_silent` на control-потоке), а в UI — понятная ошибка с причиной и командой установки (нет `libasound` / нет `pipewire-alsa` / нет устройств). Диагностика: `classify_alsa_failure`, `diagnose_alsa_failure` в `crates/daw-app/src/realtime.rs`. |
| 6 | Плашка BPM на линейке пряталась под заголовками и не тащилась; темп вне диапазона карты ломал экспорт и метроном | **Исправлено (v0.1.33, PR #70).** Первая точка — фиксированный якорь: не тащится, BPM правится двойным кликом; диапазон темпа приведён к 30–300 везде (включая скалярный `set_tempo`). |

## Используемые технологии

- Rust 2024 edition, toolchain 1.85, workspace из трёх крейтов.
- `eframe`/`egui` 0.33 (glow + x11), `rfd` для диалогов файлов.
- `winit` 0.30.13 из `vendor/winit` с патчем XDND → `CursorMoved` (см. выше).
- `cpal` 0.15 (опционально, фича `realtime`): WASAPI на Windows, ALSA/PipeWire
  на Linux.
- `symphonia` 0.5 (фичи `mp3`, `flac`, `vorbis`, `ogg`) — декодирование MP3,
  FLAC и OGG Vorbis без внешних библиотек; `hound` — WAV; `rtrb` — SPSC-очереди;
  `thiserror` — ошибки.
- Без `serde`: проект хранится в текстовом JSON с разбором руками (SPEC-008).
- `cargo fmt`, `clippy -D warnings`, `cargo test`; GitHub Actions CI и Release.

## Важные решения по архитектуре

1. **Движок не знает про платформу.** `audio-core` не подключает аудиоустройств;
   всё, что трогает ОС, живёт в `daw-app`.
2. **Без `unsafe`.** `#![forbid(unsafe_code)]` в движке и оболочке.
3. **Реальный путь без аллокаций и блокировок.** Параметры сглаживаются,
   команды идут через `rtrb`, переполнение — не паника, а отбрасывание.
   Дорогие структуры (топология шин, темпо-карты) строятся до аудио-пути и
   освобождаются на control-потоке.
4. **Один путь конвертации тик↔сэмпл.** Скалярного BPM больше нет: всё идёт
   через темпо-карту (SPEC-054), поэтому метроном, сетка, линейка и экспорт не
   расходятся между собой.
5. **Golden-тесты — оракул DSP.** `crates/audio-core/tests/golden/*.wav` не
   меняются агентом никогда; расхождение чинится в коде.
6. **Текстовый проект вместо бинарного.** Читаемость и диффы важнее размера.
7. **Офлайн-путь обязателен.** `selftest` и `bounce` работают без звуковой
   карты, поэтому тесты и агенты не зависят от оборудования.
8. **Версия из тега.** `Cargo.toml` не бампается, версия вычисляется из имени
   тега в `release.yml`.
9. **Разделение ролей агентов.** Координатор не пишет код; Opus-сессии
   реализуют; DeepSeek-сессии гоняют гейт и выпускают релизы.
