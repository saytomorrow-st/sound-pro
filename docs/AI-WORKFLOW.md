# Как мы работаем с ИИ в этом репозитории

## Принцип

ИИ получает автономию там, где результат проверяется за секунды без слуха и без
звуковой карты. Всё остальное — ревью человека.

| Зона | Кто пишет | Как проверяется |
|---|---|---|
| Архитектура аудиопотока, протоколы SPSC | человек | ревью, `docs/REALTIME.md` |
| Парсеры, форматы, CLI, сериализация | агент | юнит- и property-тесты |
| Тесты и генераторы граничных случаев | агент | тесты тестов (sanity) |
| DSP по формулам | агент + человек | golden-файлы, спектр, THD |
| UI-каркас | агент | скриншот- и e2e-тесты (следующий этап) |
| Goldens | **только человек** | прослушивание + отдельный PR |

## Цикл задачи

1. **Спецификация** (`specs/NNN-*.md`) — человек или агент по шаблону.
2. **Тикет для агента** — по шаблону в `AGENTS.md`.
3. **Агент** правит код и запускает `cargo fmt`, `cargo clippy`, `cargo test`.
4. **CI** повторяет то же самое на Linux и Windows и запрещает изменения
   goldens.
5. **Ревью** — человек смотрит diff, а не пишет код.

## Артефакты, которые держат агентов в рамках

- `AGENTS.md` — правила проекта.
- `.github/workflows/ci.yml` — единственный источник истины «зелёно/красно».
- `goldens-untouched` job — технический запрет менять оракул.
- `crates/audio-core/tests/golden.rs` — требует `UPDATE_GOLDENS=1`, чтобы
  сгенерировать эталоны; в CI переменная отсутствует.

## Первые 5 задач для агента (рекомендуемый порядок)

Спецификации готовы и лежат в `specs/`; каждую делайте отдельной веткой и PR.

| # | Спека | Что получается | Почему в этом порядке |
|---|---|---|---|
| 1 | [SPEC-002](../specs/002-incremental-wav-recorder.md) | инкрементальная запись WAV с частями | самая узкая задача, тренирует цикл агента на знакомом коде |
| 2 | [SPEC-003](../specs/003-transport-command-queue.md) | SPSC-очередь команд, UI → аудио | открывает путь к интерактивности, проверяется без железа |
| 3 | [SPEC-004](../specs/004-midi-smf-parser.md) | парсер SMF с фаззингом | изолированный новый модуль, идеален для агента |
| 4 | [SPEC-005](../specs/005-realtime-cpal-backend.md) | рабочий CPAL-бэкенд | требует железа для прослушивания, поэтому после чистых модулей |
| 5 | [SPEC-006](../specs/006-live-parameter-channel.md) | живой канал параметров (атомики) | первый код, который слышно: ручка громкости без разрыва звука |

## Как запускать задачу (пошагово)

1. Ветка: `git switch -c task/002-recorder`.
2. В Copilot Chat: `/implement-spec` и номер спеки (например «реализуй
   `specs/002-incremental-wav-recorder.md`»).
3. Агент обязан пройти gate: `cargo fmt`, `cargo clippy -D warnings`,
   `cargo test --workspace --all-targets`.
4. Проверьте сами, что тесты не ослаблены: `git diff origin/main -- '*test*'`
   должен добавлять код, а не удалять утверждения.
5. Задача «guard: goldens untouched» в VS Code должна быть зелёной.
6. PR → CI (`fmt + clippy + test` на Ubuntu и Windows) → мерж.

Если спека неоднозначна — правьте спеку, а не догадывайтесь в коде: агент
реализует только то, что записано.

## Что мерить

- Время `cargo test` в CI (рост > 1,5× — повод чистить).
- Число golden-файлов и их суммарный размер (в git, до ~10 МБ).
- Количество `#[allow(...)]` в `audio-core` (рост — сигнал, что правила просят
  обойти).
