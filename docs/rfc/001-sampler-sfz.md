# RFC-001: сэмплер и поддержка SFZ

Статус: approved (владелец, с правками §6/§8) · Владелец: saytomorrow · База: `main` (v0.1.44) · Только дизайн, кода нет.

## 0. Контекст

План «генерировать свои сэмплы» заменён на «играть чужие свободные библиотеки».
Сегодня «инструмент» один: `daw_app::piano` рендерит ноты MIDI-клипа в `Vec<f32>`
из 30 встроенных mp3 Salamander (`include_bytes!`), на контрольном потоке, при
загрузке сессии (`load_session_cached` → `ClipCache::notes`). Дальше это обычный
`SharedClip`, который играет `Track`. Живого сэмплера в аудиопотоке нет.

Решение владельца (дословно): «если есть качественный инструмент на который нужна
ссылка, то берем. мы не чураемся использовать хорошие источники». Следствие:
CC-BY допустим, качество важнее строгости лицензии; атрибуция — полноценная
функция, а не строчка в README (§6).

## 1. Цели и не-цели v1

Цели:
- Играть банки в формате SFZ (подмножество §2) с сэмплами WAV/FLAC.
- Инструмент как источник за существующим контрактом: `NodeProcessor` (аудиопоток)
  и тот же путь предрендера клипов, что у `piano`.
- Банки скачиваются по запросу, с манифестом лицензии, контрольными суммами и
  экраном авторов. В AppImage/zip банки не кладутся.
- Ноль аллокаций, блокировок и I/O в колбэке; доказывается тестом в `hot_path.rs`.

Не-цели v1: SF2/SF3, ARIA-расширения, скрипты, keyswitch, legato, фильтры и LFO,
свой редактор банков, запись банков, редактирование сэмплов, MIDI-вход с
клавиатуры (в коде не проверялся — вынесено в §8), мультитембральность
в одном узле, потоковая подгрузка (PR 7, §3.3).

## 2. Подмножество SFZ v1

Структура: `<control>` (`default_path`), `<global>`, `<master>`, `<group>`,
`<region>` с наследованием вниз; `#include`, `#define` (простые `$var`);
комментарии `//` и `/* */`. Неизвестный опкод — предупреждение в отчёте
загрузки, регион остаётся. Неизвестный заголовок/секция — пропускается.

| Опкод | Смысл |
|---|---|
| `sample` | путь относительно `default_path` и файла `.sfz`; WAV/FLAC |
| `key`, `lokey`, `hikey`, `pitch_keycenter` | диапазон нот и корень; `key=N` задаёт все три |
| `lovel`, `hivel` | диапазон velocity 1..=127 |
| `tune` (центы), `transpose` (полутоны) | подстройка |
| `volume` (дБ), `amp_veltrack` (0..100, по умолчанию 100) | громкость по velocity: `gain = 10^(volume/20) · (1 − t + t·(vel/127)²)`, `t = amp_veltrack/100` (кривая SFZ v1: квадрат) |
| `pan` | −100..100, закон из `audio_core::pan_law` (без дубля) |
| `loop_mode` (`no_loop`, `one_shot`, `loop_continuous`, `loop_sustain`), `loop_start`, `loop_end` | зацикливание; при отсутствии — значения из метаданных файла игнорируются в v1 |
| `offset`, `end` | окно в сэмпле |
| `ampeg_attack`, `ampeg_hold`, `ampeg_decay`, `ampeg_sustain`, `ampeg_release` | огибающая, секунды/проценты; линейные отрезки, релиз — от текущего уровня (как `Voice` в synth.rs) |
| `group`, `off_by`, `off_mode` (`fast`/`normal`) | группы обрезания (хэт) |
| `trigger` (`attack`, `release`) | `release` нужен пианино; ограничен: один релиз-сэмпл на NoteOff |
| `seq_length`, `seq_position` | простой round-robin: счётчик на регион-группу |
| `lorand`, `hirand` | детерминированный ГПСЧ по номеру ноты, не по времени (воспроизводимость) |

Вне рамок: `fil_*`, `eq*`, `lfo*`, `*_oncc*`, `sw_*` (keyswitch), `sw_previous`,
legato/`lokey`-скрипты, `<curve>`, `<effect>`, `region_label`, ARIA `*_curvecc`,
`#include` за пределами папки банка (запрет `..` и абсолютных путей — безопасность).
Если банк использует опкоды вне подмножества и теряет звучание существенно,
манифест помечает его `"supported": false`; решение — аудит по банку (§6).

## 3. Архитектура голосов

### 3.1 Полифония и вытеснение
- Пул голосов фиксирован: `[SamplerVoice; N]`, `N = 64` по умолчанию, максимум
  128, задаётся при создании узла (как `MAX_VOICES = 16` в `Synth`).
- Выбор голоса на NoteOn: свободный → иначе жертва по порядку:
  1) голоса в стадии release, самый тихий; 2) самый старый удерживаемый с
  минимальной velocity; 3) сам же новый голос не стартует (никогда не блокируем).
- Вытеснение — быстрый fade-out жертвы за 5 мс (≈240 сэмплов при 48 кГц), чтобы
  не щёлкало; новый голос стартует с точки события (сэмпл-точная нарезка квантом,
  как в `Synth::render`).
- Группы `off_by`: NoteOn региона обрывает голоса группы (fast = 5 мс,
  normal = их `ampeg_release`).
- Счётчики для диагностики (`stolen`, `dropped_starts`) — атомики, читает UI.

### 3.2 Интерполяция
- По умолчанию линейная (совпадает с текущим `render_piano`, поведение пианино
  не меняется). Позиция чтения — `f64`, шаг `ratio = 2^((key − root)/12 + tune/1200)
  · file_rate/out_rate` (формула уже есть в `piano::playback_ratio`; выносим и
  переиспользуем, не копируем).
- Опция качества: 4-точечный Hermite (cubic). Windowed-sinc — только для
  офлайн-экспорта (PR 7, по желанию).
- Цикл: на границе `loop_end` позиция заворачивается; без кроссфейда в v1,
  банки с плохими петлями — известный риск.

### 3.3 Preload против streaming и бюджет RAM

Формат в памяти: `i16` PCM, интерливинг не нужен (два `Arc<[i16]>` или один с
`channels`), перевод в `f32` на лету при чтении. `i16` вдвое дешевле `f32`;
24-битные FLAC теряют младшие биты — приемлемо для инструмента, помечено в §7.

| Параметр | Значение |
|---|---|
| Бюджет RAM банка по умолчанию | 512 МиБ суммарно на проект (настройка 128–2048 МиБ) |
| Верх жёсткого лимита | 2 ГиБ; превышение — отказ загрузки банка с ошибкой, не OOM |
| Размер сэмпла в памяти | `frames · channels · 2` байт; 48 кГц стерео = 192 КиБ/с |
| Голоса | 64 (до 128); память голоса — единицы КиБ (только указатели и состояние огибающей) |
| Scratch узла | `max_quantum` · 2 канала · `f32`, один раз в конструкторе |

v1 — **полная предзагрузка** (всё декодируется в RAM при установке/загрузке
банка, вне аудиопотока). Банк объявляет `ram_estimate_mib` в манифесте; если оно
больше бюджета, предлагается облегчённый профиль (`"profiles": ["full","lite"]`:
`lite` = меньше слоёв velocity и без release-сэмплов), иначе ошибка.

PR 7 (потоковая подгрузка, опционально): голова сэмпла остаётся в RAM
(например 65 536 кадров стерео `i16` = 256 КиБ; 480 сэмплов ≈ 120 МиБ), хвост
подтягивается потоком. Каждому голосу — своё SPSC-кольцо `rtrb` фиксированной
ёмкости (например 32 768 кадров), которое заполняет дисковый поток. Underrun:
голос плавно затухает за 5 мс, счётчик `underruns` растёт, аудиопоток не ждёт.
Поток из FLAC читается только вперёд; для банков, которым это дорого,
манифест может указывать WAV-зеркало (§7).

## 4. Реалтайм-анализ: поток данных от диска до колбэка

```text
контрольный/загрузочный поток                        аудиопоток (колбэк)
────────────────────────────                        ────────────────────
.sfz текст ─ parse ─► SfzDocument (pure)
файлы .flac/.wav ─ symphonia ─► Vec<i16>   (I/O и аллокации здесь)
         └► SampleBank { regions[], samples: Vec<Arc<[i16]>> }  // иммутабельный
Arc<SampleBank> ─ rtrb::Producer<SamplerMsg> ──►  SamplerNode::process:
                                                    pop сообщений (try, без блока)
                                                    подмена Arc (move, без alloc)
                                                    старый Arc ─ rtrb retire ─► контр. поток дропает
Schedule + ScheduleCursor (как PolySynth) ───────►  next_event → NoteOn/NoteOff
                                                    voices[..N] → scratch → output
```

Что ограничено и почему:
- **Работа за квант**: `N · frames · 2` чтений и умножений плюс огибающая; цикл
  по голосам фиксированной длины, пустые пропускаются. Оценка (замерить в
  бенче PR 3): 64 голоса · 256 кадров · 2 канала ≈ 33 тыс. интерполяций, на
  порядки ниже дедлайна 5,3 мс при 48 кГц/256.
- **Поиск региона**: таблица `[[RegionRef; MAX_PER_KEY]; 128]` строится при
  загрузке; на NoteOn — индексирование по ноте и линейный просмотр ≤ `MAX_PER_KEY`
  (64, остальное отбрасывается при загрузке с предупреждением). Никаких `HashMap`
  и сортировок.
- **События за квант**: `next_event` уже ограничен квантом; верхний предел
  стартов за квант — `N`, лишние считаются в `dropped_starts`.
- **Дропы `Arc`**: освобождение памяти в аудиопотоке — это `free`, а значит
  потенциально блокировка. Поэтому узел **никогда не дропает** `Arc<SampleBank>`:
  вытесненный банк уходит в кольцо `retire` (`rtrb`), контрольный поток
  опустошает его. Если кольцо полно — подмена банка откладывается на следующий
  квант (новая версия ждёт в слоте), без ожидания.
- **Установка банка**: сообщение `Install(Arc<SampleBank>)` — это перемещение
  одного указателя; ёмкость кольца 8, переполнение → UI получает `Err` и повторяет.
- **Ошибки на входе**: пустые регионы, нулевые сэмплы, битые индексы отсекаются
  при загрузке; в `process` нет `unwrap`/`expect`/непроверенных индексов.
- **Детерминизм**: позиции от абсолютного сэмпла старта (как в `Synth`), не от
  размера кванта; round-robin и `lorand` — от номера ноты и счётчика.

### Где нужен `unsafe` и почему его избегаем
1. Атомарная подмена `Arc` (`arc-swap` и т. п.) — `unsafe` внутри чужого крейта;
   **не берём**: хватает `rtrb` с перемещением `Arc`, плюс `retire`.
2. `mmap` сэмплов — `unsafe`, плюс page fault в колбэке (блокирующий I/O в
   прикрытии). **Запрещено**; только предзагрузка/поток с диска вне колбэка.
3. SIMD-интринсики (`std::arch`) — `unsafe`; **не нужны**, цикл с `chunks_exact`
   и `f32` автовекторизуется. `audio-core` остаётся `#![forbid(unsafe_code)]`,
   `daw-app` тоже.
4. Свой lock-free SPSC — **не пишем**, `rtrb` уже в workspace.

Если измерения покажут, что без `unsafe` недостижим целевой дедлайн, это
отдельный RFC, не часть v1.

## 5. Где что живёт

Принцип: чистое — в `audio-core`, ввод-вывод и платформа — в `daw-app`, окна —
в `daw-gui`. Зависимость остаётся GUI → app → core.

`crates/audio-core/src/sampler/` (новый модуль, без I/O, без внешних зависимостей):
- `sfz.rs` — `parse(text: &str, resolver: &mut dyn IncludeResolver) -> Result<SfzDocument, SfzError>`;
  чтение файлов для `#include` делегируется вызывающему (трейт в core, реализация
  в app), поэтому core по-прежнему ничего не открывает.
- `region.rs` — `Region`, таблица ключей, выбор по `(key, velocity, seq, rand)`.
- `voice.rs` — `SamplerVoice`, огибающая, интерполяция (чистые функции).
- `engine.rs` — `SamplerEngine`: пул голосов, вытеснение, группы, `render(schedule,
  cursor, position, frames, out_l, out_r)` по образцу `Synth::render`.
- `bank.rs` — `SampleBank` (иммутабельные данные: регионы + `Arc<[i16]>`).
- `lib.rs` — экспорт; ошибки в стиле `GraphError` (`SamplerError`, `thiserror`).

`crates/daw-app/src/`:
- `nodes.rs` — `SamplerNode: NodeProcessor` рядом с `PolySynth`; стерео-выход
  (`output.channels() > 1` как в `Track::process`), параметр `gain` через
  `ParamHandle` как у `PolySynth`. Один и тот же `SamplerEngine` используется
  узлом и офлайн-рендером.
- `instrument.rs` — трейт `Instrument { fn render_notes(&self, notes: &[Note],
  rate: u32, frames: u64) -> Result<Vec<f32>, SynthError>; fn id(&self) -> &str }`.
  `piano` реализует его без изменения поведения; `SamplerInstrument` — для
  банков. `load_session_cached` вызывает `Instrument` вместо `piano::render_piano`
  (`lib.rs`, ветка `clip.notes`); ключ `ClipCache::notes` расширяется id
  инструмента (иначе кэш отдаст чужой звук).
- `sample_bank.rs` — загрузка: разбор `.sfz`, декодирование через
  `audio_file::decode_with_symphonia` (SPEC-053; FLAC/WAV, без ALSA/C), перевод в
  `i16`, ресемплинг к частоте проекта — по желанию при установке (кэш рядом с
  банком), в v1 — на лету по `ratio`.
- `bank_library.rs` — каталог банков, манифесты, пути, проверка сумм.
- `bank_download.rs` — HTTP + SHA-256 + распаковка (PR 6).
- `piano.rs` — остаётся встроенным fallback (30 mp3 Salamander) до появления
  скачанного банка; `PIANO_CREDIT` переезжает в общий список авторов.

`crates/daw-gui/src/`: диалог «Банки», выбор инструмента на дорожке в инспекторе
(`TrackKind::Instrument`), окно «Авторы» (сейчас строка `PIANO_CREDIT` в
`main.rs`, About). Логика — в чистых функциях `lib.rs`, как принято (ARCHITECTURE).

Модель сессии: `Track` получает `instrument: Option<InstrumentRef>`
(`{ bank_id, program }`), сериализация в `project.rs` с умолчанием `None` для
старых файлов (правило «новые поля читаются с умолчаниями»). Нужна SPEC-062.

Тесты: `crates/audio-core/tests/sampler.rs`, `sfz_parser.rs`;
`crates/daw-app/tests/sampler_node.rs`, новый тест в `hot_path.rs`
(1000 квантов, ноль аллокаций, первый квант без прогрева). Эталоны не трогаем;
качество проверяем аналитически (частота, огибающая, уровень по velocity), а не
через `tests/golden/*.wav`.

## 6. Управление библиотекой банков

### Расположение
- Linux: `$XDG_DATA_HOME/sound-pro/banks/<bank_id>/`, по умолчанию
  `~/.local/share/sound-pro/banks/`.
- Windows: `%LOCALAPPDATA%\sound-pro\banks\<bank_id>\`.
- Кэш декодирования (если появится) — рядом с существующим `pcm_cache`
  (`~/.cache/sound-pro/pcm`), банки — это данные, не кэш.
- Переопределение: настройка «Папка банков» и пользовательские банки, которые
  человек положил сам (без манифеста — помечаются «локальный, лицензия не
  проверена»).

### Манифест банка (`bank.json`; каталог — файлы манифестов в репозитории, `catalog/banks/*.json`)
```json
{
  "schema": 1,
  "id": "salamander-grand-v3",
  "name": "Salamander Grand Piano V3",
  "version": "3",
  "category": "piano",
  "author": "Alexander Holm",
  "source_url": "https://…",
  "license_check": { "url": "https://…", "sha256": "…", "mode": "text-hash" },
  "license": { "spdx": "CC-BY-3.0", "version": "3.0", "url": "https://creativecommons.org/licenses/by/3.0/",
               "notice": "Salamander Grand Piano by Alexander Holm, CC-BY 3.0" ,
               "attribution_required": true, "audited": "2026-…", "audited_by": "…" },
  "sfz": "SalamanderGrandPianoV3.sfz",
  "format": "flac",
  "profiles": [ { "name": "full", "ram_mib": 0, "download_mib": 0, "files": [ { "path": "…", "url": "https://upstream/…", "sha256": "…", "size": 0 } ] } ],
  "supported_opcodes_ok": true
}
```
Числа (`ram_mib`, размеры, суммы) заполняются при аудите банка, в RFC они
намеренно не выдуманы. Обязательные поля: `id`, `license.spdx`,
`license.notice`, `author`, `source_url`, у каждого файла — `url` (оригинал у автора), `sha256` и `size`; также `license_check`.
Манифест без них не устанавливается (жёсткая ошибка).

### Проверенные факты о лицензиях (не перепроверяются в RFC)
| Банк | Источник | Лицензия | Статус |
|---|---|---|---|
| VSCO-2-CE (оркестр, SFZ) | sgossner/VSCO-2-CE | CC0-1.0 | проверено |
| Osiris Piano (рояль) | sfzinstruments | CC0-1.0 | проверено |
| virtuosity_drums (ударные) | sfzinstruments | CC0-1.0 | проверено |
| jlearman.SteelDrum | sfzinstruments | Unlicense | проверено |
| FreePats (напр. Upright Piano KW; SFZ+FLAC / SF2) | freepats.zenvoid.org | CC0-1.0 у KW; **по банку** | большинство не проверено |
| Salamander Grand Piano v3 | — | CC-BY-3.0 | проверено; **атрибуция обязательна в приложении**; рекомендуемое пианино |
| jRhodes3d и прочие Karoryfer | — | неизвестно | **не проверено** → аудит до включения |

### Допустимые лицензии
| Семья | Позиция |
|---|---|
| CC0-1.0, Unlicense, MIT/BSD (для сэмплов) | в каталог, без ограничений |
| CC-BY 3.0/4.0 | **в каталог**, но только с обязательной атрибуцией (ниже); решение владельца |
| CC-BY-SA, GPL-подобные | **не в стандартный каталог**: share-alike действует на «адаптации» и неоднозначно распространяется на готовые записи пользователя; допустимо только как *локальный* банк, поставленный самим пользователем, с предупреждением; юридический вывод — вопрос владельцу (§8) |
| NC, ND | **запрещены** в каталоге: NC ломает коммерческое использование пользовательской музыки, ND запрещает перепитчивание, которым и является сэмплер; локальный импорт — с предупреждением |
| «free for personal use», без явной лицензии | запрещены |

Аудит лицензии **перед включением любого банка в каталог** — обязательный шаг
процесса. Банки, чьё происхождение не проверено (jRhodes3d и прочие Karoryfer),
в каталог не попадают, пока аудит не пройден и результат не записан в манифест.
Для FreePats аудит — по каждому банку отдельно (лицензия задана по банку, не по
сайту). Для Salamander отдельно проверяется, не добавляет ли SFZ-конвертация
сторонний набор условий поверх CC-BY-3.0.

### Атрибуция как функция
1. Манифест — единственный источник (поля выше).
2. Экран загрузки показывает автора, лицензию, источник и `notice` **до**
   скачивания; скачивание — только после явного «Принять».
3. Окно «Авторы» (в About) строится из манифестов установленных банков, а
   *также* из встроенного (`PIANO_CREDIT`), и показывает: название, автор,
   лицензия, ссылка, notice. Для CC-BY — `attribution_required` отмечено значком.
4. При экспорте проекта в WAV/MP3 («Микс») диалог напоминает, какие банки с
   обязательной атрибуцией использованы в проекте; кнопка «Скопировать список
   авторов» кладёт готовый текст в буфер обмена. Тип «автоматически вшивать в
   метаданные файла» — вне v1.
5. Файл `LICENSE.txt`/`CREDITS.txt` банка копируется в папку банка и не удаляется.

### Хостинг: мы ничего не хостим (решение владельца)
Ни банков, ни архивов в наших Releases. Каталог — манифесты в репозитории
(`catalog/banks/*.json`), каждый указывает на **оригинальные** URL (GitHub,
archive.org, сайты авторов) с закреплёнными SHA-256 файлов. Приложение читает
каталог из встроенной копии (обновляется релизом приложения); внешнего сервера
каталога нет. Журнал лицензионного аудита лежит в репозитории рядом
(`catalog/audit/<bank_id>.md`: дата, кто, текст лицензии, SPDX, хэш).

### Перепроверка лицензии перед КАЖДОЙ загрузкой
Порядок в `bank_download.rs` (до скачивания данных):
1. Скачать `license_check.url` (текст лицензии/страница/`LICENSE`/метаданные
   релиза; лимит размера 1 МиБ, таймаут 10 с).
2. Нормализовать (UTF-8, обрезка пробелов, LF) и сравнить SHA-256 с
   `license_check.sha256`, затем SPDX-id (если источник отдаёт метаданные, напр.
   GitHub API `license.spdx_id`) с `license.spdx`.
3. Совпало → показать экран принятия (автор, лицензия, notice) → качать файлы.
4. Иначе — **загрузка заблокирована**, данные не качаются.

Сбои и UX:
| Случай | Поведение |
|---|---|
| Нет сети / таймаут / 5xx | блок: «Не удалось проверить лицензию; повторите онлайн». Кнопка «Повторить». Установленные банки продолжают работать |
| Upstream переехал (404/redirect на другой хост) | блок, «Источник изменился», запись в отчёт для владельца каталога; редирект на тот же хост — разрешён |
| Хэш лицензии не совпал | блок, предупреждение «Лицензия у автора изменилась, банк не может быть загружен до повторного аудита»; показать diff-хэши |
| SPDX не совпал | то же |
| Хэш файла банка не совпал | ошибка, частичные файлы удалены |
| Источник не отдаёт стабильный текст | в манифесте `mode: "metadata"` (только SPDX/`license_check` по API); решает аудит |
Приложение **не** предлагает «качать всё равно». Уже установленные банки не
перепроверяются при запуске (сеть при старте не нужна); перепроверка — при
обновлении и переустановке. Лицензия, принятая при загрузке, сохраняется в
`LICENSE.txt` банка (§ атрибуция).

### Интерфейс
**Первый запуск и выбор инструмента без банка (как в Logic Pro).** При первом
запуске, а также когда на дорожке выбран сэмплерный инструмент, банк которого не
установлен, показывается диалог: «Для инструментов нужны звуки (≈ N МиБ).
**Скачать звуки сейчас** / **Позже**». «Позже» ничего не качает и запоминается
(повторно — только при выборе инструмента без банка). В бинаре нет сэмплов,
кроме существующего запасного пианино. Первый набор: Salamander + Osiris Piano.
Нажатие «Скачать» запускает перепроверку лицензии и экран принятия (выше).

Диалог «Банки»: список из встроенного каталога, статус (не установлен /
установлен / обновление), размер загрузки и RAM, прогресс, отмена, удаление.
Скачивание: временный файл → проверка SHA-256 → атомарное переименование (тот же
приём, что в `pcm_cache`).
Повреждённая сумма → ошибка и удаление частичных файлов. Сеть — отдельный
поток; результат в UI через `std::sync::mpsc`, UI опрашивает раз в кадр
(как фоновый импорт).

Зависимости для сети/распаковки (чистый Rust, без системных библиотек):
HTTP-клиент с rustls (разрешено владельцем), `sha2`, `zip`, `serde_json` (разрешено). Выбор и цена по размеру
бинарника — в SPEC PR 6; `rustls` по умолчанию использует `ring`, который
собирается C-компилятором на машине сборки (у пользователя ничего не
требуется) — отмечено как риск в §7.

## 7. Риски и альтернативы

Риски:
- Размер и RAM у больших банков (Salamander — сотни МиБ сжатого, на порядок
  больше распакованного; точные цифры — при аудите): профили `lite`, бюджет RAM,
  потоковая подгрузка (PR 7).
- Качество петель и release-сэмплов в чужих банках, нестандартные опкоды:
  `supported`-флаг и отчёт предупреждений при загрузке.
- Лицензии: ошибка в аудите = юридический риск; каталог только по принципу
  «аудит записан в манифест».
- Ресемплинг 44,1↔48 кГц на лету (линейная интерполяция) — лёгкий алиасинг на
  больших транспозициях; смягчается Hermite.
- Сеть и TLS: `rustls`/`ring` требует C-компилятора на машине сборки (у
  пользователя ничего); принято владельцем.
- Зависимость от upstream: автор может удалить/переместить файлы или сменить
  лицензию → загрузка блокируется (перепроверка), банк недоступен; зеркала нет
  сознательно. Смягчение: уже установленные банки работают офлайн; журнал аудита.
- Декодирование FLAC при загрузке — в фоне с прогрессом; 24-бит → `i16` (§3.3), при слышимой потере — `f32`-профиль (RAM ×2).

Альтернативы:
- **SF2 вместо SFZ.** SF2 — один бинарный файл, проще распространять, парсится
  без текста; но ограниченная модуляция, слабое распространение современных
  банков и нет открытого формата для сэмплов по отдельности; бинарный разбор
  (RIFF) — много кода для меньшей выразительности. Выбор: SFZ (текстовый,
  дружелюбен к git/аудиту, большинство CC0 банков из брифа — SFZ).
- **WAV вместо FLAC.** WAV — проще, дешёвое seek для потоковой подгрузки, но
  в 2–2,5 раза больше трафика и диска. Выбор: FLAC для распространения (SPEC-053
  уже даёт декодер), в RAM — всё равно `i16`; для потоковых банков PR 7 —
  опциональное WAV-зеркало.
- **Предрендер против живого узла.** Только предрендер (как `piano`) — ноль
  риска реалтайма, но без живой игры и с перерендером при правке нот; только
  живой узел — нужен реалтайм-путь инструментальных дорожек. Берём оба:
  `SamplerEngine` общий, предрендер — как в PR 3, живой узел — в PR 4.
- **Бандлить `sfizz` / `sf2-rs` / `oxisynth`.** Чужой код в аудиопути: `sfizz` —
  C++ (нарушает «ничего лишнего»), готовые Rust-крейты не проверены на
  аллокации и `unsafe`. Пишем своё подмножество (≈ 1–1,5 тыс. строк движка).

## 8. Вопросы владельцу — решения

Приняты владельцем:
1. Каталог: сначала Salamander v3 + Osiris Piano, потом ударные, потом оркестр.
2. Бюджет: 512 МиБ RAM, 64 голоса.
3. CC-BY-SA/GPL: только локальный импорт с предупреждением.
4. **Хостинг: не хостим ничего.** Каталог — манифест в репозитории со ссылками на
   оригиналы и закреплёнными SHA-256; перед каждой загрузкой — перепроверка
   лицензии (§6). *Изменено относительно черновика.*
5. `rustls`/`ring` разрешены.
6. MIDI-входа в v1 нет; живой узел отложен (предрендер клипов).
7. Встроенное пианино остаётся как fallback.
8. Атрибуция при экспорте: диалог + кнопка «Скопировать список авторов».
9. `serde_json` разрешён.
10. Журнал аудита — в репозитории рядом с каталогом (`catalog/audit/`).

Новое по решению владельца: диалог первого запуска «Скачать звуки сейчас /
Позже» (§6, PR 5–6).

Остаётся открытым (мелкое):
- Для источников без стабильного текста лицензии (только страница сайта) —
  принимать режим `metadata` или требовать `LICENSE` в репозитории автора?
- Допустим ли редирект на другой хост того же владельца (напр. GitHub → CDN)?
