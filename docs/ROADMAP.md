# Дорожная карта Sound Pro

Здесь — «что дальше и в каком порядке». Полный список закрытых спецификаций
(001–068) описан в `docs/PROJECT_STATE.md` и `specs/`.

Каждая строка — отдельный PR и отдельный релиз. Одна задача за раз.

## Сейчас: папки дорожек (`specs/055-*.md`, в работе)

Следующий блок — группировка дорожек в папки, как Track Stack в Logic: папка
сворачивает дочерние дорожки в одну строку на таймлайне и в микшере.
Спецификация ещё не влита в `main`; до неё код не пишется (правило 2).

## Отложено

- Перетаскивание окна за полосу (SPEC-050 §1): у окна нет панели, за которую
  его тянуть. Кнопки окна в фуллскрине работают (v0.1.34). Вернуться, если
  владелец попросит.

## Ближайший горизонт (v0.1.35 – v0.1.40)

- Папки дорожек (SPEC-055, в работе).
- Живая проверка владельцем SPEC-051 — SPEC-054 (микшер с шинами и посылами,
  экспорт с нормализацией, импорт FLAC/OGG, темпо-полоса).

## Средний горизонт

- MIDI-редактор: квантизация по нотам, велосити мышью.
- Библиотека лупов на собственных сэмплах.
- Плагинная модель: эффекты как отдельные динамические модули.
- Собственный DnD для Wayland (сейчас приложение идёт через XWayland).
- Анализ громкости LUFS и автосведение.

## Правила движения

1. Одна задача — один PR — один тег.
2. Без спецификации код не пишется: сначала `specs/NNN-*.md` с критериями
   приёмки и граничными случаями.
3. Тесты пишутся до реализации; golden-файлы не трогаются.
4. Фича готова только после ручной проверки пользователем. Отчёт агента без
   живой проверки — гипотеза, а не результат.
5. Регрессия важнее новой функции: баг от пользователя идёт вперёд очереди.

## Не входит в план

- `unsafe` в движке и оболочке.
- Платформенные API в `audio-core`.
- Изменение golden-эталонов агентом.
