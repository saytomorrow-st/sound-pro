# Живой канал параметров (SPEC-006)

Параметры — это **значения** (громкость, панорама, частота фильтра). Команды из
[SPEC-003](REALTIME.md) — это **структура** (play, stop, seek, tempo). Канал
разделяет их намеренно: команда несёт побочный эффект и должна исполниться
целиком, параметр — это просто число, которое плавно доезжает до нового
значения за время сглаживания.

## Две двери к аудиопотоку

```text
UI / агент / CLI                               аудиопоток
─────────────────                              ──────────
CommandQueue::try_push  ── rtrb SPSC ────────► Renderer::render: pop_next → Transport
ParamHandle::set        ── Arc<AtomicU32> ───► NodeProcessor::process:
                                               param.next(frames, sample_rate)
```

## Почему параметры — атомики, а не вторая `rtrb`-очередь

- **Частота записи.** Слайдер мыши присылает десятки значений в секунду, а
  автоматизация — сотни. Очередь пришлось бы либо переполнять (и терять
  последнее важное значение), либо копить задержку. Атомик же хранит
  **последнее** значение, и это ровно та семантика, которая нужна параметру.
- **Нет аллокации в `set`.** `set` — два `Release`-записания в
  предвыделенную `Arc`; вызывающая сторона не проверяет `Err(Full)`.
- **Гранулярность.** Очередь требует «взять слот на каждое значение», атомик —
  «одно слово на параметр», выделенное при регистрации.

Очередь остаётся правильным выбором там, где важен **порядок и полнота**:
транспортные команды, лог событий, запись.

## Контракт

```rust
let spec = ParamSpec::new(ParamId(0), "tone.level", 0.0, 1.0, 0.5, 10)?;
let level = ParamHandle::new(spec);
graph.register_param(level.clone())?;      // в контрольном потоке
// узел держит свой клон handle
level.set(0.25);                           // из любого потока
let v = self.level.next(ctx.frames, ctx.sample_rate);  // в узле
```

- `next` вызывается **один раз за квант** и возвращает значение на начало
  кванта; узел размножает его на свои `frames`. Значение фиксировано на весь
  квант — это и есть шаг сглаживания.
- Сглаживание линейное, длиной `smoothing_ms`; `smoothing_ms == 0` — мгновенный
  скачок (`next` сразу отдаёт цель).
- Значение на выходе всегда в `[min, max]`: `set` клампит, `NaN` игнорируется.
- `set` того же значения не перезапускает рамку.
- Повторный `set` посреди рамки стартует из **текущего** значения рамки, без
  скачка.
- `next`, `set`, `value` не аллоцируют, не блокируют, не паникуют.
- Стоимость: два атомарных чтения и два атомарных записывания за квант на
  параметр.

## Ограничения

- Параметр не знает частоты дискретизации: длина рамки вычисляется в `next`,
  поэтому **смена частоты во время рамки** не определена (вне области
  SPEC-006).
- Одновременный `set` из двух потоков даёт одно из двух значений, а не
  смесь; порядок не определён.
- Реестр параметров фиксированной ёмкости (`Graph::with_capacity(..., max_params)`):
  регистрация сверх неё — `ParamError::RegistryFull`, без аллокации.
