# SPEC-062: парсер SFZ (текст, подмножество v1)

Статус: ready
Владелец: saytomorrow
Для агента: разрешено реализовывать

Файлы: `crates/audio-core/src/sampler/` (новый модуль `mod.rs` + `sfz.rs`),
`crates/audio-core/tests/sfz_parser.rs`, `crates/audio-core/tests/fixtures/`.

Ссылка: `docs/rfc/001-sampler-sfz.md`, разделы 2 (подмножество SFZ v1) и 5
(где что живёт). Это PR 1 вертикального среза: только чистый текстовый парсер,
без аудио, без realtime-пути, без GUI, без изменения формата проекта.

## Проблема

Сэмплер (RFC-001) нуждается в чтении банков SFZ. Первый шаг — превратить текст
`.sfz` в типизированный список регионов, не касаясь сэмплов, декодера и
аудиопотока. RFC §5 предписывает парсеру жить в `audio-core/src/sampler/sfz.rs`
с сигнатурой `parse(text, resolver)`; чтение файлов для `#include` делегируется
вызывающему через трейт, поэтому `audio-core` по-прежнему не открывает файлы.

## Поведение

1. `parse(text: &str, resolver: &mut dyn IncludeResolver) -> Result<SfzDocument, SfzError>`
   — чистая функция: нет I/O, нет паники на мусоре, нет `unsafe`.
2. Разбираются заголовки `<control>`, `<global>`, `<master>`, `<group>`,
   `<region>`; опкоды наследуются вниз по иерархии `control → global →
   master → group → region` (более глубокий уровень перекрывает родителя).
   Неизвестный заголовок/секция пропускается целиком (его опкоды не попадают в
   результат и не влияют на наследование).
3. Поддерживаются директивы `#include "путь"` (разрешается через
   `IncludeResolver`; запрещены абсолютные пути и `..` — безопасность) и
   `#define $var value` / `#define $var 1` с подстановкой `$var` в значениях
   опкодов. Неопределённая переменная — предупреждение, значение подставляется
   как пустая строка.
4. Комментарии `//` (до конца строки) и `/* ... */` (многострочные)
   игнорируются.
5. `default_path` из `<control>` попадает в документ и используется как базовый
   каталог для разрешения `sample` (сам парсер пути не читает).
6. Для подмножества v1 (таблица RFC §2) строится типизированный список
   `Region`: `sample`, `key`/`lokey`/`hikey`/`pitch_keycenter`, `lovel`/`hivel`,
   `tune`, `transpose`, `volume`, `amp_veltrack`, `pan`, `loop_mode`,
   `loop_start`, `loop_end`, `offset`, `end`, `ampeg_attack`/`_hold`/`_decay`/
   `_sustain`/`_release`, `group`, `off_by`, `off_mode`, `trigger`,
   `seq_length`/`seq_position`, `lorand`/`hirand`.
7. Неизвестный опкод — предупреждение в отчёте загрузки; регион остаётся в
   результате. Предупреждения никогда не превращаются в ошибку.
8. Некорректный ввод (незакрытая директива `#include`/`#define`, нечисловое
   значение там, где нужно число, выходящий за диапазон `key`/`lovel` и т.п.)
   возвращает типизированную `SfzError` с байтовым смещением, не паникует.

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| пустой ввод | `Ok`, пустой список регионов |
| заголовок без опкодов (`<region>` пустой) | регион с унаследованными значениями |
| `key=60` | задаёт `lokey=hikey=pitch_keycenter=60` |
| `lokey` > `hikey` | `SfzError::InvalidRange { at }` |
| `lovel`/`hivel` вне `1..=127` | `SfzError::InvalidRange { at }` |
| `#define $x 5` затем `volume=$x` | `volume` = 5 |
| `#include` с `..` или абсолютным путём | `SfzError::UnsafePath { path }` |
| `#include` несуществующего файла | ошибка от `resolver` пробрасывается как `SfzError::Include` |
| неизвестный опкод (`fil_type=...`) | предупреждение, регион остаётся |
| неизвестный заголовок `<effect>` | секция пропускается без предупреждения об опкодах |
| нечисловое значение (`key=abc`) | `SfzError::InvalidNumber { at }` |
| незакрытый `/*` | `SfzError::UnterminatedComment { at }` |

## Критерии приёмки

- [ ] Юнит-тесты на каждый опкод подмножества v1 и на наследование.
- [ ] Интеграционные тесты `sfz_parser.rs` на маленьких рукописных `.sfz`
      фикстурах (без реальных банков и аудиофайлов).
- [ ] Битые входы: минимум 6 случаев из таблицы, каждый — `Err`, не паника.
- [ ] `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D
      warnings`, `cargo test --workspace --all-targets` зелёные (offline-путь;
      фича `realtime` не собирается локально из-за отсутствия `libasound2-dev`,
      проверяется CI-джобой «realtime backend build»).
- [ ] Ни одной новой зависимости и ни одного платформенного API в `audio-core`.

## Вне области

Декодирование WAV/FLAC, загрузка сэмплов, `Region`-таблица выбора по
`(key, velocity, seq, rand)`, `SamplerVoice`, `SamplerEngine`, `SampleBank`,
нода `SamplerNode`, каталог банков, скачивание банков — это PR 2–7 RFC-001.
Расширения ARIA, `fil_*`, `eq*`, `lfo*`, keyswitch, `<curve>`, `<effect>` и
скрипты — вне подмножества v1.
