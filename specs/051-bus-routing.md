# SPEC-051: Глубокая маршрутизация шин

Статус: ready
Владелец: saytomorrow
Для агента: разрешено реализовывать

## Проблема

SPEC-028 дал шины только как «приёмники»: дорожки шлют в шину посылы, шина
смешивается в мастер. Шина не может отправить часть своего сигнала в другую
шину (например, задержка → реверб), у шины нет кнопок S/M, а цикл «шина →
шина → шина» можно построить в JSON и получить зацикливание или молчаливый
сбой при построении графа. Надо дать шинам собственные посылы, запретить
циклы, добавить solo/mute и показать всё это в микшере, не сломав старые
проекты и не нарушив контракт реального времени.

## Поведение

### Модель (`audio_core::session`)

- `Bus` получает поля `sends: Vec<BusSend>` (посылы шины на другие шины, по
  умолчанию пусто), `mute: bool`, `solo: bool` (по умолчанию `false`).
  `Bus::new(name)` сохраняет прежние значения (`gain = 1`, без эффектов, без
  посылов, не заглушена, не соло).
- Индексы в `Bus::sends` адресуют `Session::buses`; посыл шины не может
  ссылаться на саму шину (цикл из одной дуги) и не может повторять одну шину.
- `Session::is_bus_audible(bus)` — `true`, когда шина не заглушена и либо
  ничего не соло, либо она соло; mute сильнее solo; неверный индекс — `false`.
- `validate` дополнительно:
  - для каждой шины проверяет её посылы тем же правилом, что посылы дорожки
    (`SessionError::InvalidSend { track, send }`, где `track` — индекс шины),
    плюс запрещает самоссылку;
  - отклоняет цикл между шинами
    (`SessionError::InvalidSend { track: <шина, с которой начинается дуга
    цикла>, send: <индекс дуги> }`);
  - запрещает посыл на заглушённую/соло-неактивную шину не нужно: solo/mute
    на шине влияет только на её возврат в мастер и на её посылы дальше (см.
    ниже), а не на существование посыла.

### Звук (`daw_app::nodes::Mixer`)

- Порядок обработки шин — топологическая сортировка по их посылам; считается
  один раз при построении `Mixer` (вне аудиопотока) и передаётся внутрь узла
  как готовый `Vec<usize>`. Если топологическая сортировка невозможна (цикл),
  граф не строится — это та же ошибка, что уже поймана `validate`.
- В `process` (без аллокаций, блокировок и I/O):
  1. каждая дорожка рендерится как раньше; её стерео-выход идёт в микс, а
     выход × `level` — во входы шин-приёмников (посыл после фейдера;
     заглушённая/неактивная дорожка ничего не шлёт — как в SPEC-028);
  2. шины обрабатываются в топологическом порядке: для каждой шины суммируются
     входы от дорожек и от предыдущих шин (по их посылам), прогоняются её
     эффекты (по одному набору на канал), умножаются на `gain`;
  3. если шина активна (solo/mute) — её обработанный сигнал прибавляется к
     миксу; посыл активной шины на другую шину передаётся дальше независимо от
     её solo/mute-состояния (solo/mute шины управляет только её возвратом в
     мастер, чтобы посылы не «рвались» при соло);
  4. мастер-громкость применяется один раз ко всей сумме.
- Буферы выделяются при построении; `process` не аллоцирует.

### JSON (`audio_core::project`)

- У шины необязательные ключи `"sends": [{"bus": 0, "level": 0.5}]`,
  `"mute": true`, `"solo": true` — пишутся только когда непусто/не `false`.
- Старые проекты (без этих ключей) читаются без изменений: посылы пустые,
  mute/solo `false`. Неизвестные ключи по-прежнему отклоняются.

### Редактор (`daw_gui::Editor`)

- `set_bus_send(bus, target, level)` — уровень посыла шины `bus` на шину
  `target`; `level = 0` убирает посыл; запрещает самоссылку и цикл
  (`EditorError::Session(SessionError::InvalidSend { .. })`), оставляя `self`
  неизменным. Каждый успешный вызов — один шаг отмены.
- `set_bus_mute(bus, mute)`, `set_bus_solo(bus, solo)` — переключают флаги
  шины; одно изменение — один шаг отмены; задание текущего значения шага не
  создаёт.
- `remove_bus` дополнительно удаляет посылы на эту шину со всех шин и
  дорожек и сдвигает индексы посылов на шины после неё (как уже делает для
  дорожек).

### Окно (`daw_gui::shell`)

- В полосе шины — кнопки `M` и `S` (как на дорожке): mute глушит возврат
  шины, solo оставляет только соло-шины (и не разрывает посылы).
- Выбор назначения отправки: в полосе шины (в полном виде, как у дорожек)
  список посылов на другие шины с ползунком уровня; выбор шины-приёмника
  делается через выпадающий список доступных шин (без самоссылки). Невалидный
  выбор (цикл) не применяется.

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| Самоссылка `bus.sends → bus` | `InvalidSend`, правка не применяется |
| Цикл `A → B → A` | `InvalidSend`, правка не применяется |
| `set_bus_send` с `level = 0` на отсутствующий посыл | ничего не меняется, шага отмены нет |
| `set_bus_send` на неверную шину/приёмник | `NoBus`, `self` неизменен |
| Соло на шине | в мастере слышны только соло-шины; посылы продолжают течь |
| Mute на шине | возврат шины в мастер тихий; её посылы на другие шины всё ещё идут |
| Старый проект без `buses[].sends/mute/solo` | читается как раньше (посылы пусты, mute/solo `false`) |
| Шина без посылов и эффектов | рендер бит-в-бит как в SPEC-028 |

## Критерии приёмки

- [ ] Юнит-тесты модели: валидация посылов шин, запрет цикла/самоссылки,
      `is_bus_audible` (solo/mute).
- [ ] Тесты рендера (через `bounce`, без аудиоустройства): посыл шины на шину
      складывается в правильном порядке, solo/mute шины влияют только на
      возврат, мастер-громкость применяется один раз.
- [ ] JSON: круговой проход посылов шин и mute/solo; старые файлы читаются.
- [ ] Editor: `set_bus_send`, `set_bus_mute`, `set_bus_solo`, расширенный
      `remove_bus` — по одному шагу отмены, невалидные значения не меняют
      `self`.
- [ ] `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D
      warnings`, `cargo test --workspace --all-targets` зелёные (включая
      windows-ветки `cfg(target_os)`).
