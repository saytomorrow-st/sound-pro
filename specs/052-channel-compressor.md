# SPEC-052: Компрессор и другие эффекты канала

**Статус:** черновик  
**Владелец:** audio-core, daw-app, daw-gui  
**Для агента:** расширение существующего компрессора мягким коленом и индикатором gain reduction, добавление гейта и лимитера как отдельных эффектов канала.

## Проблема

В SPEC-022 компрессор имеет только жёсткое колено (hard knee), что даёт резкий переход при достижении порога. Профессиональные DAW предлагают мягкое колено (soft knee) для более музыкального звучания, а также отдельные процессоры динамики: гейт для подавления тихих участков и лимитер для защиты от клиппинга.

Кроме того, отсутствует визуальная обратная связь о работе компрессора — музыканту нужен индикатор gain reduction (GR), показывающий, насколько сигнал ослаблен в данный момент.

## Поведение

### Компрессор: мягкое колено

К существующему `EffectKind::Compressor` добавляется параметр `knee_db` (дБ, `0..=24`):

- При `knee_db = 0` поведение идентично текущему (жёсткое колено): gain reduction начинается точно на пороге.
- При `knee_db > 0` переход от unity gain к полной компрессии размазывается на `knee_db` децибел ниже и выше порога.

**Алгоритм мягкого колена** (квадратичная интерполяция):

Пусть `L` — уровень огибающей в дБ, `T` — порог (`threshold_db`), `W` — ширина колена (`knee_db`), `slope = 1 - 1/ratio`.

1. Если `2·(L - T) < -W`: сигнал далеко ниже порога, `gain_reduction_db = 0`.
2. Если `|2·(L - T)| ≤ W`: сигнал внутри колена,  
   `gain_reduction_db = slope · (L - T + W/2)² / (2·W)`.
3. Если `2·(L - T) > W`: сигнал выше колена,  
   `gain_reduction_db = slope · (L - T - W/2)`.

Make-up gain применяется после компрессии, как и раньше.

### Индикатор gain reduction

`EffectProcessor` получает метод `gain_reduction_db(&self) -> f32`, возвращающий величину ослабления в дБ (всегда ≥ 0) для последнего обработанного блока. Компрессор запоминает максимальное GR за вызов `process`, остальные эффекты возвращают `0.0`.

В `daw-app` модуль `meters` дополняется структурой или полем для хранения GR всех эффектов всех треков в атомарных `u32` (как `Meters`). `Track::render` записывает GR каждого эффекта после `render_unmetered`, если метр включён. GUI опрашивает эти значения в `poll_meters` и отображает в инспекторе эффектов рядом со слайдерами компрессора.

### Гейт

Новый тип `EffectKind::Gate`:

- `threshold_db`: порог открытия, дБFS, `-80..=0`.
- `range_db`: глубина подавления (attenuation) закрытого гейта, дБ, `0..=80`. При полностью закрытом гейте сигнал ослабляется на `range_db` дБ. Значение 80 дБ даёт практически полную тишину.
- `attack_ms`: время открытия, мс, `0.1..=100`.
- `hold_ms`: время удержания открытого состояния после падения огибающей ниже порога, мс, `0..=500`.
- `release_ms`: время закрытия, мс, `10..=1000`.

**DSP:** одно-пóльная огибающая пика (как у компрессора). Состояния: «закрыт», «атака», «удержание», «спад». Переходы:

- Закрыт → атака: когда огибающая превышает порог.
- Атака → удержание: когда коэффициент гейта достигает 1.0.
- Удержание → спад: когда огибающая падает ниже порога и истекло `hold_ms`.
- Спад → закрыт: когда коэффициент достигает `db_to_gain(-range_db)`.
- Спад → атака: если огибающая снова превысила порог.

Коэффициент изменяется по экспоненте с константами `c_attack = exp(-1 / (attack_ms · Fs))` и `c_release = exp(-1 / (release_ms · Fs))`. В состоянии «удержание» коэффициент остаётся равным 1.0.

### Лимитер

Новый тип `EffectKind::Limiter`:

- `ceiling_db`: потолок выходного уровня, дБFS, `-24..=0`.
- `release_ms`: время восстановления, мс, `10..=1000`.

**DSP:** пиковый лимитер с мгновенной атакой (instant attack) и экспоненциальным восстановлением. Огибающая строится по абсолютному значению входа; если огибающая превышает потолок, коэффициент усиления мгновенно падает до `ceiling / envelope`. Затем огибающая плавно снижается с константой релиза `c_release = exp(-1 / (release_ms · Fs))`, и коэффициент следует за ней.

Альтернативная упрощённая реализация: жёсткий клиппинг на уровне потолка без сглаживания (для первой итерации допустимо).

### Параметры по умолчанию

- `EffectKind::compressor()` остаётся `-18 dB, 4:1, 10 ms, 100 ms, 0 dB makeup`, добавляется `knee_db: 0.0` (жёсткое колено).
- `EffectKind::gate()`: `threshold_db: -40.0`, `range_db: 60.0`, `attack_ms: 1.0`, `hold_ms: 50.0`, `release_ms: 100.0`.
- `EffectKind::limiter()`: `ceiling_db: -0.5`, `release_ms: 50.0`.

### Сериализация

**Компрессор:** поле `knee_db` опционально при чтении (по умолчанию `0.0`), записывается только когда `knee_db != 0.0`, чтобы старые файлы сохранили свою структуру.

**Гейт и лимитер:** новые типы `"gate"` и `"limiter"` с соответствующими ключами. Все поля обязательны при их наличии.

### Автоматизация

Новые параметры:

- `KneeDb` (ключ `"knee_db"`, диапазон `0..=24`).
- `GateThresholdDb` (`"gate_threshold_db"`, `-80..=0`).
- `GateRangeDb` (`"gate_range_db"`, `0..=80`).
- `GateAttackMs` (`"gate_attack_ms"`, `0.1..=100`).
- `GateHoldMs` (`"gate_hold_ms"`, `0..=500`).
- `GateReleaseMs` (`"gate_release_ms"`, `10..=1000`).
- `CeilingDb` (`"ceiling_db"`, `-24..=0`).
- `LimiterReleaseMs` (`"limiter_release_ms"`, `10..=1000`).

Все имена уникальны. `EffectParam::ALL` растёт с 30 до 38 элементов.

### GUI

**Названия эффектов:**

- `EffectKind::Compressor`: «Компрессор».
- `EffectKind::Gate`: «Гейт».
- `EffectKind::Limiter`: «Лимитер».

**Кнопки добавления:** «+ Гейт», «+ Лимитер» в окне эффектов трека/шины.

**Слайдеры:** для каждого параметра в `EffectParam::of(kind)`, с русскими метками из `param_label`.

**Индикатор GR компрессора:** текстовое поле или прогресс-бар, показывающий `"{gr:.1} дБ"` или `"—"` когда GR = 0. Обновляется при опросе метров (~60 Гц).

## Граничные случаи

| Условие                                  | Поведение                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| `knee_db = 0` (компрессор)               | Жёсткое колено, как в SPEC-022                                                 |
| `range_db = 0` (гейт)                    | Закрытый гейт не ослабляет сигнал, эффект становится бесполезным               |
| `range_db = 80` (гейт)                   | Закрытый гейт даёт практически полную тишину (~−80 дБFS)                       |
| `ceiling_db = 0` (лимитер)               | Защита от превышения 0 дБFS                                                    |
| `hold_ms = 0` (гейт)                     | Нет удержания, гейт закрывается сразу при падении огибающей ниже порога        |
| Все параметры гейта на минимуме          | Гейт открывается мгновенно при любом сигнале, закрывается очень медленно       |
| Все параметры лимитера на максимуме      | Потолок −24 дБFS, очень медленное восстановление                               |
| Компрессор + гейт + лимитер в одной цепи | Обработка последовательная; порядок определяется пользователем через GUI       |
| GR > 24 дБ (компрессор или лимитер)      | Допустимо; индикатор показывает фактическое значение                           |
| Автоматизация `knee_db`, `range_db`      | Параметры меняются ступенчато каждые `EFFECT_AUTOMATION_STEP` кадров          |
| Проект без `knee_db` (старая версия)     | Читается как `0.0`, звук идентичен                                             |
| Проект с типом `"gate"` или `"limiter"`  | Старые версии, не знающие этих типов, отвергнут документ (неизвестное поле)   |

## Критерии приёмки

- [ ] `EffectKind::Compressor` имеет поле `knee_db: f32`.
- [ ] `EffectKind::Gate` и `EffectKind::Limiter` определены с полями выше.
- [ ] `EffectKind::gate()` и `EffectKind::limiter()` возвращают значения по умолчанию.
- [ ] `type_name()` возвращает `"gate"` и `"limiter"`.
- [ ] `is_valid()` проверяет диапазоны всех новых параметров.
- [ ] `EffectParam::ALL` содержит 38 элементов; assert в тесте обновлён.
- [ ] `EffectParam::of()` возвращает корректные срезы для гейта и лимитера.
- [ ] DSP компрессора реализует мягкое колено по формуле выше; при `knee_db = 0` поведение идентично SPEC-022.
- [ ] `Compressor::process` запоминает максимальное GR за блок.
- [ ] `EffectProcessor::gain_reduction_db()` возвращает GR компрессора или `0.0`.
- [ ] DSP гейта реализует четыре состояния и экспоненциальные переходы.
- [ ] DSP лимитера реализует мгновенную атаку и экспоненциальное восстановление (или жёсткий клипп).
- [ ] `State` включает варианты `Gate` и `Limiter`.
- [ ] `EffectProcessor::new`, `update` и `process` поддерживают гейт и лимитер.
- [ ] Проект читает `knee_db` как опциональное поле (по умолчанию `0.0`) и пишет его только когда `!= 0.0`.
- [ ] Проект читает и пишет `"gate"` и `"limiter"` со всеми их полями.
- [ ] Юнит-тесты в `fx.rs`:
  - компрессор с `knee_db = 0` идентичен старому,
  - компрессор с `knee_db > 0` даёт плавный переход,
  - гейт открывается при превышении порога и закрывается при падении,
  - лимитер ограничивает пики не выше потолка.
- [ ] Round-trip тесты в `project.rs` для всех трёх типов.
- [ ] Все литералы `EffectKind::Compressor { .. }` дополнены полем `knee_db: 0.0`.
- [ ] `daw-app/src/meters.rs` содержит хранилище GR (или расширен `Meters`).
- [ ] `Track::render` записывает GR эффектов в метр.
- [ ] `daw-gui/src/main.rs`:
  - `effect_title` возвращает «Гейт» и «Лимитер»,
  - `effect_sliders` показывает слайдеры для всех параметров,
  - кнопки «+ Гейт» и «+ Лимитер» добавляют эффекты,
  - `param_label` содержит русские метки для всех 8 новых параметров,
  - инспектор компрессора показывает GR из метров.
- [ ] `cargo build --workspace` проходит без ошибок.
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` чист.
- [ ] `cargo test --workspace --all-targets` зелёный.

## Вне области

- Сайдчейн (гейт/компрессор по внешнему сигналу).
- Look-ahead (упреждающий анализ для лимитера).
- Многополосная динамика.
- Визуальная кривая gain reduction или histogram.
- Автоматическое gain reduction для гейта или лимитера (только компрессор имеет индикатор).
- Обновление golden-тестов: при расхождении чинится код, а не эталоны.
