# SPEC-004: Парсер MIDI-файла (SMF, тип 0 и 1)

Статус: ready
Владелец: команда движка
Для агента: разрешено реализовывать

Файлы: `crates/audio-core/src/midi.rs` (новый), `crates/audio-core/tests/`, `docs/`

## Проблема

Нужен первый источник нот для будущего плейбека. Спецификация SMF публична;
никакой код и данные из Logic/других DAW не используются (clean-room).

## Поведение

1. `parse_smf(bytes: &[u8]) -> Result<MidiFile, MidiError>` — только чтение из
   байт, без I/O и без паники на мусоре.
2. Поддерживаются заголовки `MThd` (формат 0 и 1, division в PPQN; SMPTE-деление
   возвращает `UnsupportedDivision`), треки `MTrk`, событие `EndOfTrack`.
3. Отдавать: номер трека, абсолютный тик, `NoteOn`/`NoteOff` (включая
   `velocity == 0` как `NoteOff`), `Tempo` meta в микросекундах на четверть.
4. Running status поддерживается; всё неизвестное пропускается по длине.
5. Результат сортируется по `(tick, track, order_in_track)` — детерминирован.

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| пустой ввод | `MidiError::Empty` |
| обрезанный трек (длина меньше заявленной) | `MidiError::Truncated { at }` |
| `NoteOn` без парного `NoteOff` в конце трека | нота считается отпущенной на `EndOfTrack` |
| `velocity > 127`, длина события `0` | `MidiError::Malformed { at }` |
| 10 МБ случайных байт | `Err`, не паника, время < 1 с (тест) |

## Критерии приёмки

- [ ] Табличные юнит-тесты на каждый тип события и на running status.
- [ ] Битые входы: минимум 6 случаев из таблицы.

- [ ] `docs/` — короткая заметка о поддержанных возможностях SMF.
