# SPEC-054: Трек темпа (tempo track)

Статус: draft
Владелец: saytomorrow
Для агента: разрешено реализовывать

## Проблема

Проект имеет единственный темп (`Session::tempo_bpm`), который действует на
всю песню и считается в долях размера. Музыкант не может изменить темп по
ходу композиции (ritardando, смена части, резкий срез), а все места, где
темп используется (метроном, сетка/снэп, линейка тактов, MIDI-секвенсер,
экспорт/офлайн-рендер), читают этот одиночный BPM независимо и расходятся в
интерпретации «тика» и «сэмпла».

## Поведение

### Модель (`audio_core`)

- Новый тип `TempoPoint { position_ticks: u64, bpm: f64 }` и упорядоченная
  по `position_ticks` карта `TempoMap` (список точек). Первая точка всегда
  на `position_ticks == 0`.
- `Session` получает поле темпа как список точек. Обратная совместимость:
  одиночный `tempo_bpm` проекта становится первой (и единственной) точкой.
  Существующий аксессор `tempo_bpm` продолжает возвращать BPM первой точки.
- `Session::validate` возвращает ошибку, если список пуст, первая точка не в
  нуле, точки не отсортированы по `position_ticks`, BPM точки не конечен или
  вне `30.0..=300.0`, или точек больше `MAX_TEMPO_POINTS`.
- Смена темпа — скачком (step), без рамп.

### Преобразование тики ↔ сэмплы

- Одна общая функция/структура преобразует `samples → ticks` и
  `ticks → samples` через темпо-карту, без дублирования.
- Отрезок между соседними точками имеет постоянный темп (темп точки,
  предшествующей концу отрезка). Кумулятивные сэмпл-позиции начал отрезков
  предвычисляются вне аудиопути.
- Все места, использующие одиночный BPM, переходят на карту: метроном,
  сетка/снэп, линейка тактов, MIDI-секвенсер, экспорт/офлайн-рендер.

### Realtime-безопасность

- В аудиопотоке (`Graph::process`, `Renderer::render`, аудиоколбэк) — ни
  аллокаций, ни блокировок, ни логов.
- Карта строится вне аудиопути: предвычисленный срез кумулятивных
  сэмпл-позиций сегментов, поиск сегмента — бинарный поиск по готовому
  срезу. Передача карты в аудиопоток переиспользует существующий механизм
  передачи состояния (атомики/рингбуфер), без нового lock-free механизма.

### Сериализация (`Project`)

- Ключ `"tempo_map"` внутри `"session"`: массив точек `[position_ticks,
  bpm]`. Пишется только когда точек больше одной, так что старые проекты и
  их текст не меняются. Старый формат (без ключа) открывается как одна
  точка с текущим `tempo_bpm`.

### Редактор (`daw_gui`)

- Дорожка темпа под линейкой с точками.
- Добавление — двойной клик; перетаскивание; удаление; редактирование BPM в
  диапазоне `30.0..=300.0`.
- Все правки идут через существующую систему команд Undo/Redo (одно
  действие отмены на правку), проект помечается изменённым.

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| Одна точка | поведение бит-в-бит с прежним одиночным BPM (goldens не меняются) |
| Несколько точек | тики↔сэмплы считаются кусочно-постоянным темпом |
| Точка в середине доли | сегмент начинается ровно на её тике |
| Удаление/перетаскивание первой точки | не допускается (первая всегда в нуле) |
| BPM вне 30–300 | отклоняется `validate` |
| Старый проект без карты | открывается как одна точка |

## Критерии приёмки

- [ ] Юнит-тесты на преобразование тики↔сэмплы туда-обратно.
- [ ] Тест «одна точка == прежнее поведение»: goldens бит-в-бит.
- [ ] Тест «несколько точек» на кусочно-постоянный темп.
- [ ] Round-trip сериализации и чтение старого формата.
- [ ] Тест отсутствия аллокаций в `process` (hot path).
- [ ] `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`,
      `cargo test --workspace --all-targets` зелёные.

## Вне области

- Рампы темпа (плавные изменения), автоматизация BPM, смена размера по ходу
  песни, отдельный звук метронома, отсчёт перед записью.
