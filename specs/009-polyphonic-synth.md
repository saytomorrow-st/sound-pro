# SPEC-009: Полифонический синтезатор (Schedule → голоса)

Статус: ready
Владелец: команда движка
Для агента: разрешено реализовывать

Файлы: `crates/audio-core/src/synth.rs` (новый модуль),
`crates/audio-core/src/{lib.rs,graph.rs}`, `crates/daw-app/src/{nodes.rs,lib.rs,main.rs}`,
`crates/audio-core/tests/`, `docs/SYNTH.md`, `docs/REALTIME.md`

## Проблема

После SPEC-007 аудиопоток умеет **узнавать** события (`Schedule::next_event`),
но звука из них не делает: `MidiPlayer` только считает. Демо-граф играет
синусоиду, не связанную с MIDI-файлом. Нужен узел, который из
`NoteOn`/`NoteOff` собирает **голоса** и суммирует их — первый по-настоящему
«инструментальный» звук проекта, и он же проверяемый без железа (offline).

## Поведение

1. Новый модуль `audio-core/src/synth.rs`, публичный как `audio_core::synth`
   и реэкспортированный из корня. Чистый DSP без I/O, без аллокаций на
   горячем пути, без `unsafe`.

   ```rust
   pub const MAX_VOICES: usize = 16;

   /// Один голос: независимый осциллятор с огибающей.
   pub struct Voice { /* … */ }

   /// Полифония с выделением голосов и мягким вытеснением.
   pub struct Synth {
       voices: [Voice; MAX_VOICES],
   }
   ```

2. **Ноты → частота.** Равномерная темперация, A4 = 440 Гц:

   ```text
   freq(note) = 440 * 2^((note - 69) / 12)
   ```

   `note` — `0..=127`. Частота считается **один раз** в момент `NoteOn`
   (в контрольном потоке её никто не пересчитывает), дальше голос живёт на
   ней. Функция `pub fn note_to_hz(note: u8) -> f64` публична и тестируется
   отдельно: `69 → 440`, `57 → 220`, `81 → 880`, погрешность < 1e-9.

3. **`NoteOn`.** Ищет свободный голос (не занятый, `gain == 0`). Если
   свободных нет — вытесняет голос с **наименьшим** текущим `gain`
   (слышимо тишайший), при равенстве — самый давний по `started_at`. Вызов
   `NoteOn` для уже звучащей пары `(channel, note)` **не** добавляет второй
   голос: голос перезапускается (сброс фазы и огибающей к нулю и атака
   заново) — иначе двойной `NoteOn` удваивал бы громкость.

4. **`NoteOff`.** Освобождает **все** голоса с той же парой
   `(channel, note)`; перевод в стадию release. `NoteOff` для незвучащей
   ноты игнорируется.

5. **Огибающая (ADSR, без sustain-плато по умолчанию).** Четыре стадии,
   каждая в сэмплах, посчитанных из секунд при старте (`sample_rate`
   приходит в `process`):

   | стадия | поведение |
   |---|---|
   | attack | линейный рост `0 → peak` за `attack_s` |
   | decay | линейный спад `peak → sustain` за `decay_s` |
   | sustain | ровно `sustain` (доля от `peak`) |
   | release | линейный спад до `0` за `release_s` |

   Параметры по умолчанию: `attack_s = 0.005`, `decay_s = 0.08`,
   `sustain = 0.7`, `release_s = 0.12`. `attack_s == 0` — голос сразу на
   `peak`; `release_s == 0` — голос гаснет на первом же сэмпле release.
   Нулевая длительность не делит на ноль и не даёт `NaN`.

6. **Амплитуда ноты.** `peak = velocity / 127` (от 1/127 до 1.0). Голоса
   **суммируются** без нормализации (как в реальном микшере); клиппинг —
   забота следующего узла, здесь выход в `f32` как есть. При 16 голосах
   каждый по 1.0 выход = 16.0 — это допустимо и документируется.

7. **Суммирование и огибающая без щелчков.** Голос с `gain == 0` не
   считается (пропускается), чтобы мёртвые голоса не съедали CPU: цикл по
   `MAX_VOICES` фиксирован, ветвление по `gain`.

8. **Детерминизм.** Результат зависит только от `(schedule, sample_rate,
   position, frames)`. Один и тот же `Synth` при одинаковой последовательности
   вызовов даёт бит-в-бит тот же выход; квантование кванта (256 vs 512
   сэмплов) даёт **тот же** результат, потому что фаза и огибающая
   отсчитываются от абсолютных сэмплов, а не от «сколько прошло с прошлого
   вызова».

   Практическое следствие: голос хранит `started_at` (абсолютный сэмпл
   старта) и `released_at: Option<u64>`; фаза считается как
   `(position + i - started_at)`, а не инкрементально.

9. **`Synth::render(&mut self, schedule: &Schedule, cursor: &mut ScheduleCursor,
   position: u64, frames: usize, sample_rate: u32, out: &mut [f32])`** —
   единственный «горячий» вход:

   - заполняет `out[..frames]` (моно);
   - в начале обрабатывает все события кванта (`sample` в
     `[position, position + frames)`), применяя их **к этому же кванту**:
     сэмпл события — абсолютная позиция, поэтому голос, стартовавший на
     `s+k`, не звучит в сэмплах `0..k`. Это делается через
     `Voice::start_at(sample)`: голос помнит `started_at`, и для сэмплов
     раньше него `gain == 0`;
   - события **прошлого** (`sample < position`, курсор их пропускает) не
     звучат — так задумано: `next_event` уже перематывает курсор после seek;
   - ни одного `unwrap`/`expect`, ни одной аллокации, ни блокировок, ни
     `println!`.

10. **Узел `PolySynth` в `daw-app`.** Оборачивает `Synth` + `Schedule` +
    `ScheduleCursor` + `last_position` (как `MidiPlayer`), пишет в канал 0.
    При `ctx.position < last_position` — пересоздаёт курсор и **гасит все
    голоса** (`Synth::reset`), иначе после seek звучали бы ноты, которых уже
    нет. Параметр `synth.gain` (0..1, по умолчанию 0.5, рампа 10 мс) —
    единственный живой параметр узла, применяется к выходу.

11. **CLI.** Новая команда `daw render-midi <in.mid> <out.wav> [--tempo BPM]
    [--seconds S]`:

    - читает файл SMF (`std::fs::read`), разбирает `audio_core::midi::parse_smf`,
      строит `ScheduleSpec::from_midi(..., tail_samples = SR)`, собирает граф
      с `PolySynth`, рендерит `length_samples` (или `--seconds`, если задан)
      через существующий offline-путь и пишет WAV;
    - ошибка чтения/разбора/рендера → stderr и код выхода 1;
    - печатает число сэмплов, число нот и число голосов, стартовавших за
      рендер (счётчик `synth.voices_started`).

    Файловый I/O — только в `main.rs`, как в SPEC-008.

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| пустое расписание | ноль, без паники |
| `frames == 0` | выход не трогается, курсор не двигается |
| `NoteOn` без `NoteOff` до конца | голос звучит до release-хвоста расписания и гаснет |
| `NoteOff` без `NoteOn` | игнорируется |
| двойной `NoteOn` одной ноты | один голос, перезапущенный, не удвоение громкости |
| 17 одновременных нот | 16 голосов, вытеснен тишайший |
| `velocity == 0` после парсера | доходит как `NoteOff` (см. SPEC-004), не `NoteOn` с нулём |
| `attack_s == 0` | голос сразу на `peak` |
| `release_s == 0` | гаснет на первом сэмпле release |
| `NoteOn` на сэмпле `position + k` | сэмплы `0..k` тишина |
| seek назад в середине ноты | голоса погашены, нота не «висит» |
| `sample_rate == 0` | `SynthError::InvalidSampleRate` в конструкторе, не паника |
| 1 квант 8192 сэмпла | нет аллокации (цикл по `MAX_VOICES`), результат тот же |

## Критерии приёмки

- [ ] `note_to_hz` точен: 69→440, 57→220, 81→880, 60→261.6255653…, < 1e-9.
- [ ] Одна нота: огибающая совпадает с ожидаемой формой (attack/decay/
      sustain/release) с допуском 1e-6 в точках перехода.
- [ ] `NoteOn`/`NoteOff` в одном кванте: голос стартует точно на нужном
      сэмпле (проверяется, что сэмпл `k-1` — 0, `k` — не 0 при attack > 0).
- [ ] 17 нот → 16 голосов, вытеснен тишайший (тест проверяет конкретный id).
- [ ] Двойной `NoteOn` не удваивает амплитуду (±1 % против одной ноты).
- [ ] Независимость от размера кванта: рендер 4800 сэмплов квантами 256 и
      512 даёт бит-в-бит равный выход (как в `tests/render_quantum_tail.rs`).
- [ ] Детерминизм: два прогона байт-в-байт равны.
- [ ] `reset` гасит все голоса; после seek назад выход не содержит хвоста
      ноты, начавшейся до seek.
- [ ] `MAX_VOICES` голосов звучат без паники и без выхода в `NaN`/`inf`.
- [ ] В `synth.rs` нет `Vec::push`, `Box::new`, `format!`, `Mutex`, `println!`,
      `std::fs` (проверяется `rg`).
- [ ] `daw render-midi` пишет WAV на реальном MIDI-файле; битый файл →
      код выхода 1.
- [ ] `docs/SYNTH.md` с формулами и примером; ссылка из `README.md`.
- [ ] `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
      `cargo test --workspace --all-targets --locked` зелёные.

## Вне области

- Фильтры, резонанс, LFO, эффекты, сэмплер, модуляция.
- MIDI-каналы как отдельные инструменты (все каналы звучат одним тембром).
- Автоматизация параметров синтезатора и UI.
- Poly pressure, pitch bend, aftertouch, RPN/NRPN (парсер их не отдаёт).
- Передискретизация, антиалиасинг, таблицы волн.
- Любая правка `crates/audio-core/tests/golden/*.wav`.
