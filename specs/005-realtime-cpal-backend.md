# SPEC-005: Realtime-бэкенд CPAL (Linux ALSA / Windows WASAPI)

Статус: ready
Владелец: команда платформы
Для агента: разрешено реализовывать

Файлы: `crates/daw-app/src/realtime.rs`, `crates/daw-app/src/main.rs`, `.github/workflows/ci.yml`, `docs/`

## Проблема

`play_default` в `crates/daw-app/src/realtime.rs` — минимальный прототип: он не
учитывает фактический размер колбэка устройства, не сообщает dropped callbacks и
не умеет остановиться.

## Поведение

1. При старте выбирается конфигурация устройства с sample rate из
   `DEFAULT_SAMPLE_RATE` (48 кГц), иначе ближайшая поддерживаемая; выбор
   логируется в stderr (это fallback-поток, не аудио).
2. Колбэк: если `frames > max_quantum`, квант рендерится по частям без аллокации;
   недостающие каналы заполняются тишиной; выход дублируется из моно.
3. Счётчики `dropped_callbacks` и `rendered_frames` ведутся атомиками и
   доступны через `RealtimeHandle::stats()`.
4. `RealtimeHandle::stop()` останавливает поток без паники и join-ится < 100 мс.
5. Ошибки устройства — `Result<_, RealtimeError>`, не `panic!`/`unwrap`.
6. CI-джоба `realtime-build` собирает фичу на Linux и Windows (уже есть).

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| нет аудиоустройства | `RealtimeError::NoDevice`, код выхода 2 у CLI |
| устройство только стерео | моно дублируется в оба канала |
| частота 44.1 кГц | используется она, транспорт идёт на её частоте |
| рендер вернул ошибку | тишина в колбэке, счётчик ошибок +1 |
| два вызова `stop()` | второй — no-op |

## Критерии приёмки

- [ ] `cargo build -p daw-app --features realtime` на Linux и Windows (CI).
- [ ] Юнит-тесты на чистые функции (выбор конфигурации, разбиение кванта) без железа.
- [ ] Ручная проверка: `daw bounce` и `daw play` дают одинаковый звук (документировано).
- [ ] В колбэке нет `println!`, аллокаций, блокировок (ревью + описание в `docs/REALTIME.md`).

## Вне области

ASIO/JACK, горячая смена устройства, запись из микрофона.
