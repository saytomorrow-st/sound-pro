# SPEC-011 — Чистота горячего пути и консистентность клипа

Дата: 2026-10-29.
Приоритет: выше всех последующих спек.

Эта спека закрывает два дефекта, найденные при ревизии кода после SPEC-010.
Оба нарушают `AGENTS.md` и оба воспроизводятся в нынешнем `main`.

## 1. Аллокация на горячем пути в `Tone::process`

**Дефект.** `nodes::Tone::process` каждый квант вызывает
`wav::sine(...) -> Vec<Sample>` и копирует результат в `dst`. То есть каждая
звучащая дорожка в `daw bounce`, `daw play` и `render-session` аллоцирует
`4 * block` байт на квант и тут же их освобождает. `AGENTS.md` §«Контракт
реального времени» это прямо запрещает; `docs/REALTIME.md` тоже.
Тесты ловят `Graph::add_node`-время, а не `process`-время, поэтому CI зелёный.

**Почему это опасно.** На Linux `malloc` в аудиопотоке может взять мьютекс
аллокатора и увести колбэк за дедлайн — это классический источник щелчков.
На Windows-ASIO ситуация хуже: аллокация в колбэке CPAL — частая причина
xrun.

**Что нужно.**
1. Добавить в `audio-core::wav` (или иной подходящий модуль) безаллокационную
   форму синуса:
   ```rust
   pub fn sine_into(freq_hz: f64, sample_rate: u32, offset: u64, out: &mut [Sample]);
   ```
   Формула и порядок округления совпадают с `sine` **бит-в-бит**.
2. Выразить существующую `sine` через `sine_into`, чтобы эталонная
   зависимость между ними была одна и та же строка кода.
3. `Tone::process` считает прямо в `output.channel_mut(0)[..ctx.frames]`,
   без временного буфера.
4. В `nodes.rs` не должно остаться ни одной вызываемой из `process` функции,
   возвращающей `Vec`, `String`, `Box` или `format!`-результат.

**Критерии приёмки**
- [x] `PCM`/`f32` WAV, записанный `daw bounce` до и после изменения, совпадает
  байт-в-байт (goldens не пересчитываются и не должны измениться).
- [x] Тест `sine_into` == `sine` для нескольких частот/смещений/длин, включая
  `frames == 0`, `frames == 1` и нецелое число периодов.
- [x] Тест-сторож: `Tone::process` не аллоцирует. Реализуется через
  `#[global_allocator]`-счётчик в отдельном интеграционном тесте
  (`crates/daw-app/tests/hot_path.rs`), который обнуляет счётчик, гоняет 1000
  квантов через `Renderer::render` и требует нуля аллокаций. Счётчик не должен
  ломать остальные тесты и работать при любом числе потоков. Реализовано
  через thread-local счётчик: глобальный атомик ловит аллокации соседних
  тестов при параллельном запуске.
- [x] Тот же сторож покрывает `Track::process`, `Strip::process` и
  `MidiPlayer::process` с непустым расписанием.

## 2. `Track::process` держит копию полей клипа

**Дефект.** `nodes::PlacedClip` — это ручная копия четырёх полей
`audio_core::session::Clip` (`start_samples`, `length_samples`,
`offset_samples`, `gain`, переименованных в `start`, `length`, `offset`, `gain`).
Модель и узел могут разойтись: правка `Clip` в движке молча не доедет до
рендера, а компилятор об этом не скажет. `PlacedClip` не даёт ничего, кроме
одного переименования поля.

**Что нужно.**
1. `Track` хранит `clips: Vec<audio_core::session::Clip>` как есть; `PlacedClip`
   удаляется.
2. `Track::process` вызывает `Clip::covers` и `Clip::source_index` из модели —
   ровно те функции, что покрыты тестами в `crates/audio-core/tests/session.rs`.
3. `Session::validate` по-прежнему единственный барьер; узел не перепроверяет
   модель и не паникует на некорректных входах.

**Критерии приёмки**
- [x] `rg PlacedClip` пуст.
- [x] Поведение рендера не меняется: `crates/daw-app/tests/session.rs` зелёный
  без правки ожиданий.
- [x] Тест, который до изменения не компилировался/не проходил: клип, у
  которого `source_length` больше длины источника, не паникует и не читает за
  границей (`content.get(...)` возвращает `None` → тишина). То есть `Track`
  остаётся безопасным при рассогласовании, даже если `validate` обойдут.

## Уточнение после реализации

Первая версия сторожа прогревала рендер одним квантом, потому что общий
счётчик показывал выделения памяти на первом `render`. Это была ошибка замера:
счётчик ловил выделения соседних тестов. С thread-local счётчиком первый
`render` тоже даёт ноль, поэтому прогрев убран. Выделять память может только
конструктор (`Renderer::new`, `Graph::with_capacity`).

## Вне области

Многопоточный рендер, SIMD, вынос `Tone` в отдельный crate, замена формулы
синуса на более точную, изменения в `Graph::process`.
