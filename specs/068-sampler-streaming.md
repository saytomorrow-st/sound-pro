## Проблема

1. Движок читает сэмплы линейной интерполяцией (`read_linear_i16`,
   `read_linear_stereo` в `voice.rs`). Для сильной транспозиции и для банков с
   44.1 кГц на 48 кГц-выходе (Salamander) линейная интерполяция даёт заметный
   алиасинг и потерю верхов (RFC §7 предлагает Hermite как смягчение).
2. Банк целиком грузится в RAM (`load_bank`, `DEFAULT_RAM_BUDGET_MIB = 512`,
   `RamBudgetExceeded`). Банки крупнее бюджета не открываются вовсе.

## Рекомендация (с числами из RFC)

| Банк | Размер архива (каталог) | Бюджет preload |
|---|---|---|
| Osiris Piano | 458 671 376 Б ≈ 437 МиБ | 512 МиБ |
| Salamander Grand v3 | 488 713 261 Б ≈ 466 МиБ | 512 МиБ |

- Оба текущих банка помещаются в бюджет по умолчанию (запас 46–75 МиБ), при
  том что бюджет настраивается 128–2048 МиБ, а жёсткий предел — 2 ГиБ
  (RFC §3.3). Стриминг сегодня не решает ни одной реальной задачи.
- Стриминг даёт выигрыш по RAM: голова 65 536 стерео-кадров i16 = 256 КиБ;
  ~480 сэмплов ≈ 120 МиБ голов вместо ≈ 466 МиБ, то есть ≈ 4× меньше.
  Цена: loader-поток, кольца на голос (32 768 кадров ≈ 128 КиБ × 64 голоса ≈ 8 МиБ),
  политика underrun, новая поверхность реалтайм-багов.
- **Шаг A (Hermite) делать сейчас**: малый, изолированный, проверяемый
  офлайн, улучшает звук Salamander на 44.1→48 кГц.
- **Шаг B (стриминг) отложить**: делать, когда появится банк, не
  помещающийся в 512 МиБ после распаковки (RFC §7: порядок распакованного
  размера больше архива), либо когда пользователи упрутся в предел 2 ГиБ.
  Спека остаётся нормативной на этот случай.

## Поведение

### Шаг A. Интерполяция Эрмита

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Interpolation {
    #[default]
    Linear,
    Hermite4,
}
```

- `SamplerEngine` хранит `interpolation: Interpolation`, задаётся в
  `new_with(...)`/сеттере из контрольного потока (не из аудио-колбэка). Умолчание
  `Linear`: поведение и golden-файлы не меняются.
- Новые функции в `voice.rs`: `read_hermite_i16(data, pos, len) -> f32` и
  `read_hermite_stereo(data, pos, frames) -> (f32, f32)`. Точки `x[i-1], x[i],
  x[i+1], x[i+2]`, где `i = floor(pos)`, `t = pos - i`:

```text
c0 = x1
c1 = 0.5 * (x2 - x0)
c2 = x0 - 2.5*x1 + 2*x2 - 0.5*x3
c3 = 0.5 * (x3 - x0) + 1.5 * (x1 - x2)
y  = ((c3*t + c2)*t + c1)*t + c0
```

- Края: индексы за пределами `[0, len)` зажимаются (`x[-1] = x[0]`,
  `x[len] = x[len-1]`); для цикла индексы оборачиваются по `loop_start..loop_end`
  так же, как это делает `advance()` (без разрыва на шве петли).
- Без аллокаций и ветвлений по данным, кроме зажима индексов. `unsafe` нельзя.

### Шаг B. Потоковая подгрузка

**Режимы.** `SamplerBank { mode: Preload | Stream }`. По умолчанию `Preload`
(сегодняшнее поведение). `Stream` включается явно либо автоматически, если
оценка preload превышает бюджет, а оценка стриминга — нет.

**Структуры данных (все выделяются в контрольном потоке заранее).**

```rust
/// Иммутабельная голова сэмпла, общая для всех голосов.
pub struct SampleHead {
    pub head: Arc<[i16]>,        // первые HEAD_FRAMES (65_536) кадров или весь сэмпл
    pub total_frames: u64,       // длина всего сэмпла
    pub channels: u8,
    pub fully_resident: bool,    // сэмпл короче головы: диск не нужен
}

/// Кольцо одного голоса: SPSC, producer у loader, consumer у голоса.
pub struct VoiceStream {
    pub consumer: rtrb::Consumer<i16>,   // емкость RING_FRAMES * channels
    pub frames_played_from_ring: u64,
}
```

- `HEAD_FRAMES = 65_536`, `RING_FRAMES = 32_768` (RFC §3.3). Кольцо на каждый
  слот голоса выделяется при создании движка (64 голоса по умолчанию, до 128).
- Запрос на чтение: `rtrb::Producer<LoadRequest>` от движка к loader
  (`LoadRequest { voice, sample_index, from_frame }`, `Copy`, ёмкость ≥ числа
  голосов × 2). Готовые блоки идут **напрямую в кольцо голоса** (producer кольца
  принадлежит loader-потоку, consumer — голосу), канала ответа нет.
- Голос читает из головы, пока `pos < head_frames`; затем из кольца. Кольцо
  дозаполняется loader'ом по мере расхода: порог запроса — кольцо заполнено
  менее чем на 50 %.
- FLAC читается только вперёд; зацикливание после головы: loader перемещает
  точку чтения на `loop_start` (перемотка = переоткрытие потока в loader-потоке,
  не в аудио-потоке). Для петель, целиком лежащих в голове, диск не нужен.
- Освобождение ресурсов (закрытие файла, `Arc<SampleHead>`) — только в
  loader/контрольном потоке; аудио-поток никогда не дропает `Arc`
  (мусор — через кольцо `retire`, RFC §4).

**Границы потоков.**

| Поток | Владеет | Запрещено |
|---|---|---|
| Аудио | `Consumer<i16>` колец, `Producer<LoadRequest>`, `Arc<SampleHead>` (клон только при установке банка через `Install`) | аллокации, блокировки, I/O, дроп `Arc` |
| Loader | `Producer<i16>` колец, `Consumer<LoadRequest>`, файловые дескрипторы, декодеры | прямой доступ к состоянию голосов |
| Контрольный | загрузка банка, создание голов и колец, остановка loader'а | вызов из аудио-колбэка |

**Политика underrun (никогда не блокировать).** Если голосу нужен кадр, а
кольцо пусто, а голова исчерпана: голос переходит в затухание 5 мс (240 отсчётов
@48 кГц, то же, что `STEAL_FADE_SAMPLES`), счётчик `underruns:
AtomicU32` инкрементируется, голос освобождается. Тишина вместо ожидания;
никаких `park`, `sleep`, `lock`, `recv` в аудио-пути. Опция «подмена нулями без
обрыва ноты» не вводится.

**Бюджет RAM.** Оценка стриминга = `Σ head_bytes + voices × RING_FRAMES × channels × 2`.
`load_bank` в режиме `Stream` проверяет эту оценку по тому же бюджету
(`RamBudgetExceeded` остаётся); жёсткий предел 2 ГиБ действует для обоих режимов.
Манифест банка сообщает `ram_estimate_mib` для `full` и `stream`.

**Офлайн-экспорт (детерминизм).** `OfflineRenderer` использует тот же
`Renderer`, поэтому экспорт **не** может опираться на lossy-underrun. Правило:
`Instrument::build_engine` для офлайн-пути всегда строит движок в `Preload`
(целые сэмплы в RAM) либо в режиме `SyncStream`, где голос синхронно
дочитывает блок из контрольного/рендер-потока (допустим блок на I/O, потому что
это не аудио-колбэк). Underrun в экспорте — невозможен по построению;
`underruns` в офлайн-тестах обязан быть 0. Результат экспорта побитово равен
результату `Preload` при тех же входах и не зависит от `block_frames`
(абсолютные позиции, RFC §4).

## Граничные случаи

| Случай | Поведение |
|---|---|
| Сэмпл короче головы | `fully_resident = true`, кольцо не запрашивается |
| Голос стартует с `offset` внутри головы | читаем из головы; запрос в loader на `HEAD_FRAMES` заранее |
| Loader отстаёт | underrun: затухание 5 мс, `underruns += 1`, звук не ждёт |
| Кражa голоса / `off_by` во время подгрузки | кольцо сбрасывается контрольной командой, запрос отменяется по `generation` |
| Цикл полностью в голове | диск не используется |
| Цикл выходит за голову | loader переоткрывает поток на `loop_start` (в своём потоке) |
| Файл исчез/ошибка декодера | loader помечает сэмпл `failed`; голос получает underrun-затухание; ошибка в логе контрольного потока |
| Бюджет оценки > лимита | `RamBudgetExceeded` без загрузки; жёсткий предел 2 ГиБ |
| Остановка loader'а при закрытии проекта | контрольный поток шлёт `Shutdown`, делает `join`; аудио в это время не ждёт |
| Экспорт при режиме `Stream` | всегда `Preload`/`SyncStream`, underrun = 0 |
| Hermite у границ сэмпла/петли | индексы зажимаются/оборачиваются, без щелчка на шве |

## Тесты

Шаг A:
- **Ошибка на синусе.** Синус 1 кГц, 44.1 кГц, транспозиция +7 полутонов (и
  дробная ratio): максимальная абсолютная ошибка относительно аналитического
  значения у Hermite строго меньше, чем у линейной, не менее чем в 10× при
  частоте синуса ≤ fs/8; допуск — константа в тесте, не ослабляется.
- **Умолчание.** `Interpolation::Linear` даёт бит-в-бит прежний вывод
  (golden не трогаются).
- **Детерминизм.** Один и тот же сценарий с разными `block_frames`
  (64/256/1024) даёт одинаковый вывод для обоих режимов интерполяции.
- **Края.** Сэмпл из 1, 2, 3 кадров, позиция на последнем кадре, шов петли — без
  паники, без NaN.
- **No-alloc.** `sampler_no_alloc.rs` расширяется прогоном с `Hermite4`: полный
  жизненный цикл (128 note-on на 64 голоса, off_by, стерео, цикл, note-off), счётчик
  аллокаций не меняется.

Шаг B:
- **Эквивалентность.** При «быстром» loader (синхронная заливка в тесте)
  вывод `Stream` бит-в-бит равен `Preload` на том же сценарии.
- **Underrun.** Loader искусственно замедлен (тестовый loader отдаёт блок
  по сигналу): голос затухает за 240 отсчётов, `underruns == 1`, аудио-вызов не
  блокируется (проверяется тем, что `render` возвращается без ожидания сигнала),
  остальные голоса не затронуты.
- **Экспорт.** `OfflineRenderer` на движке из `Instrument::build_engine`
  не использует lossy-путь: `underruns == 0`, вывод равен `Preload`, не зависит от `block_frames`.
- **Бюджет.** `Stream` принимает банк, который в `Preload` даёт
  `RamBudgetExceeded`; оценка соответствует формуле (±1 КиБ).
- **No-alloc.** Расширенный `sampler_no_alloc.rs`/`hot_path.rs`: render в режиме
  `Stream` (голова + кольца, включая underrun и подгрузку) не аллоцирует.
- **Остановка.** Закрытие инструмента завершает loader-поток (`join`) без утечки.

## Критерии приёмки

Шаг A (Pro):
- [ ] `Interpolation { Linear, Hermite4 }`, умолчание `Linear`; golden не изменены.
- [ ] `read_hermite_*` без аллокаций, без `unsafe`, без паники на краях.
- [ ] Тест ошибки на синусе: Hermite ≥ 10× точнее линейной (см. выше).
- [ ] Детерминизм по `block_frames` для обоих режимов.
- [ ] `sampler_no_alloc` покрывает `Hermite4`.
- [ ] `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --all-targets` зелёные.

Шаг B (Opus; только когда принято решение делать):
- [ ] Структуры `SampleHead`, `VoiceStream`, `LoadRequest` как описано; кольца и каналы выделены заранее.
- [ ] Underrun: затухание 5 мс, счётчик, никаких блокировок; тест с замедленным loader'ом.
- [ ] Экспорт детерминирован и не использует lossy-путь; тест на `underruns == 0` и равенство с `Preload`.
- [ ] Бюджет RAM по формуле; `RamBudgetExceeded` и предел 2 ГиБ сохранены.
- [ ] No-alloc тест режима `Stream` зелёный; `Arc` не дропается в аудио-потоке.
- [ ] Loader корректно останавливается; нет `unsafe` в `audio-core`.
- [ ] Обязательный цикл (fmt, clippy, test) зелёный.

## Нельзя

- Менять `crates/audio-core/tests/golden/*.wav`, запускать `UPDATE_GOLDENS=1`.
- Ослаблять существующие тесты и допуски, добавлять `#[ignore]`.
- Использовать `mmap` (page fault = скрытый I/O в аудио-потоке, RFC §7), `unsafe`
  в `audio-core`, `Mutex`/`RwLock`/блокирующие каналы на аудио-пути.
- Дропать `Arc` или закрывать файлы в аудио-потоке.
- Допускать lossy-underrun в офлайн-экспорте.
- Менять умолчание интерполяции с `Linear` без отдельной спеки и прослушивания.
