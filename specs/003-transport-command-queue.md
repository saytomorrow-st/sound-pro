# SPEC-003: SPSC-очередь команд транспорта

Статус: implemented
Владелец: команда движка
Для агента: разрешено реализовывать
Файлы: `crates/audio-core/src/{transport.rs,graph.rs,render.rs}`, `crates/audio-core/tests/`

## Проблема

UI пока не может отправить `Play`/`Stop`/`Seek` в аудиопоток: `Graph` хранит
`Transport` напрямую и мутируется только через `&mut`. Мьютекс на горячем пути
запрещён.

## Поведение

1. Новый модуль `audio-core/src/commands.rs`: тип `CommandQueue` на базе `rtrb`
   (SPSC, без блокировок), producer — для UI, consumer — для аудиопотока.
2. `CommandQueue::new(capacity)` выделяет память; `try_push(TransportCommand)`
   возвращает `Err(Full)` вместо блокировки; `pop()` на стороне аудио не
   аллоцирует и не блокирует.
3. `Renderer::render` в начале кванта вычитывает **все** доступные команды до
   первого `Play`/`Stop`-эффекта и применяет их по порядку; результат одинаков
   независимо от того, в каком кванте команды пришли, если они пришли до него.
4. Команды, полученные во время `render`, применяются полностью в этом кванте
   или переносятся на следующий — обе стратегии недопустимы как «половина»:
   тест фиксирует единый результат.

   **Выбранная стратегия (реализовано):** `render` в начале кванта вычитывает
   всю очередь в FIFO до расчёта позиции. Команда, попавшая в очередь до
   кванта, применяется в этом кванте; попавшая после вычитки — в начале
   следующего. Зафиксировано в `docs/REALTIME.md` и в тесте
   `queue_is_deterministic_regardless_of_push_quantum`.
5. `SetTempo(0.0)` игнорируется (как в SPEC-001).

## Граничные случаи

| Случай | Ожидаемое поведение |
|---|---|
| очередь заполнена | `try_push` → `Err(Full)`, без паники на стороне аудио |
| 1000 команд за 1 квант | все применены или корректно отброшены по стратегии из п.4 |
| команды пришли между квантами | эффект ровно один раз |
| `capacity == 0` | паника в конструкторе с `# Panics` в документации |

## Критерии приёмки

- [x] Юнит-тесты `commands.rs`: заполнение, порядок, пустая очередь.
- [x] Интеграционный тест: команды `Play → Seek → Stop` дают ожидаемую позицию.
- [x] Тест детерминизма: одинаковая последовательность команд → бит-в-бит одинаковый выход.
- [x] В `Graph::process` нет `Mutex`, `Arc::new`, `Vec::push`, `format!` (проверить ревью и `rg`).
- [x] `docs/REALTIME.md` описывает очередь как единственный канал UI → аудио.

## Вне области

Многопоточный producer, автоматизация параметров, undo.
