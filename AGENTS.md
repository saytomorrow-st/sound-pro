# AGENTS.md — правила для ИИ-агентов

Этот файл читают агенты (Copilot, Claude и др.) перед любой задачей. Приоритет
правил: `AGENTS.md` > `specs/` > прочие документы.

## Что за проект

Открытая DAW на Rust для Linux и Windows. Движок (`crates/audio-core`) не зависит
от платформы и аудиоустройств; оболочка (`crates/daw-app`) подключает бэкенды.

## Обязательный цикл

Перед предложением любых изменений:

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets
```

Все три команды должны быть зелёными. Не отключайте тесты и не добавляйте в них
`#[ignore]`, не объясняя причину в описании PR.

## Контракт реального времени

Код, вызываемый из `Graph::process`, `Renderer::render` и аудиоколбэка бэкенда:

- **не аллоцирует** (никаких `Vec::push`, `Box::new`, `format!`, `collect`);
- **не блокирует** (`Mutex`, `RwLock`, блокирующие каналы запрещены);
- **не делает I/O** (файлы, сеть, env, логирование через `println!`);
- **не паникует** на неправильных входах — возвращает `Result` (образец:
  `GraphError`, `RenderError`).

Всё дорогое — в конструкторе/fallback-потоке. Обмен с UI — через `rtrb`
(SPSC-рингбуфер), выделенный при старте.

## Чего агентам делать нельзя

1. **Не менять `crates/audio-core/tests/golden/*.wav`** и не запускать
   `UPDATE_GOLDENS=1`. Эталонные файлы — оракул DSP. Если код расходится с
   эталоном, чинится код, а не эталон. Обновление эталонов — отдельный PR
   человека после прослушивания.
2. **Не ослаблять существующие тесты** (удалять assert, расширять допуск,
   менять ожидаемые значения), чтобы «пройти» сборку.
3. **Не добавлять в движок зависимости, которые тянут платформенные API** — они
   живут в `crates/daw-app`.
4. **Не трогать `clean-room/`** — это журнал метода чистой комнаты. Агенты
   «чистой» команды не должны читать материалы оттуда, если задача явно не
   разрешает (см. `clean-room/README.md`).
5. Не использовать `unsafe` в `audio-core` (стоит `#![forbid(unsafe_code)]`).

## Как добавлять функции

1. Спецификация в `specs/NNN-название.md` (критерии приёмки, граничные случаи).
2. Тесты сначала: юнит — внутри модуля, интеграционные — в `tests/`,
   golden — в `tests/golden.rs`.
3. Реализация минимального вертикального среза.
4. Прогон обязательного цикла, затем PR по шаблону.

## Dev-appimage после каждого PR

После открытия или обновления любого PR агент обязан выполнить из ветки этого PR:

```bash
scripts/dev-appimage.sh
```

Скрипт собирает `daw-gui` в release и кладёт исполняемый AppImage в папку
загрузок (`xdg-user-dir DOWNLOAD`, `~/Загрузки`; переопределяется
`DEV_APPIMAGE_DIR`). В отчёте по PR укажите путь, который скрипт напечатал
последней строкой. Если сборка упала — процитируйте ошибку в отчёте; прятать
её или выдавать старую сборку за новую нельзя.

## Шаблон задачи для агента

```
Цель: <одно предложение>
Спецификация: specs/NNN.md
Файлы, которые можно менять: <список>
Критерии приёмки:
- [ ] cargo test --workspace --all-targets зелёный
- [ ] cargo clippy ... -D warnings зелёный
- [ ] <поведенческие критерии>
Нельзя: менять goldens, ослаблять тесты, добавлять unsafe.
```

## Работа на машинах без аудиоустройства

Запускайте только offline-путь:

```bash
cargo test --workspace --all-targets
cargo run -q --bin daw -- selftest
cargo run -q --bin daw -- bounce /tmp/tone.wav 1.0
```

Флаг `realtime` (CPAL) требует ALSA-заголовков на Linux и не нужен для тестов.
